Une variable d'environnement change le comportement de Claude Code pour la session courante, sans toucher à tes fichiers de settings. Tu peux la définir dans ton shell (`export MA_VARIABLE="valeur"` puis `claude`) ou de façon persistante via la clé `env` d'un fichier `settings.json`.

::note
La doc officielle liste plus d'une centaine de variables (authentification AWS/GCP/Azure, gateways d'entreprise, options d'accessibilité très pointues...). Cette page ne garde que celles qui servent le plus souvent en usage courant — voir le lien en bas de page pour la liste complète.
::

## Où les définir

| Emplacement | S'applique à |
| --- | --- |
| Ton shell (`export ...`) | La session courante uniquement — relancer `claude` après un changement |
| `~/.claude/settings.json` (clé `env`) | Toi, dans tous les projets |
| `.claude/settings.json` (clé `env`) | Tout le monde travaillant sur ce projet |
| `.claude/settings.local.json` (clé `env`) | Toi, dans ce projet uniquement |

Les valeurs `env` d'un fichier de settings ont priorité sur les variables définies dans le shell. Pour désactiver une variable héritée, mets-la à une chaîne vide dans `env` : `"MA_VARIABLE": ""`.

## Variables courantes

| Variable | À quoi ça sert |
| --- | --- |
| `ANTHROPIC_API_KEY` | Clé API envoyée en en-tête `X-Api-Key`. Si elle est définie, elle remplace ton abonnement Claude Pro/Max/Team/Enterprise. Fais `unset ANTHROPIC_API_KEY` pour revenir à ton abonnement. |
| `ANTHROPIC_MODEL` | Nom du modèle à utiliser par défaut pour les nouvelles sessions. |
| `ANTHROPIC_BASE_URL` | Change l'URL de l'API pour router les requêtes via un proxy ou une passerelle (gateway) d'entreprise. |
| `ANTHROPIC_AUTH_TOKEN` | Valeur personnalisée pour l'en-tête `Authorization` (préfixée par `Bearer`). |
| `API_TIMEOUT_MS` | Délai avant expiration d'une requête API, en millisecondes (défaut : 600000, soit 10 minutes). À augmenter si tes requêtes expirent sur un réseau lent ou via un proxy. |
| `BASH_DEFAULT_TIMEOUT_MS` | Délai par défaut pour les commandes bash longues (défaut : 120000, soit 2 minutes). |
| `BASH_MAX_TIMEOUT_MS` | Délai maximum que Claude peut demander pour une commande bash longue (défaut : 600000, soit 10 minutes). |
| `BASH_MAX_OUTPUT_LENGTH` | Nombre maximum de caractères de sortie bash relus par Claude Code (défaut : 30000 ; maximum : 150000). |
| `MCP_TIMEOUT` | Délai que Claude Code attend qu'un serveur MCP se connecte au démarrage (30 secondes par défaut). |
| `USE_BUILTIN_RIPGREP` | Mets-la à `0` pour que Claude Code utilise le `ripgrep` installé sur ton système plutôt que celui fourni avec l'outil — utile si la recherche de fichiers ne fonctionne pas. |
| `CLAUDE_CONFIG_DIR` | Pointe vers un autre dossier que `~/.claude` pour la configuration. Pratique pour tester avec une configuration complètement vierge. |
| `CLAUDE_CODE_SCROLL_SPEED` | Change le nombre de lignes défilées par cran de molette en mode plein écran. |
| `CLAUDECODE` | Mise à `1` automatiquement dans les sous-processus lancés par Claude Code (Bash, hooks, statusline, serveurs MCP en stdio...). Sert à détecter qu'un script tourne à l'intérieur d'un sous-processus de Claude Code. |
| `DISABLE_TELEMETRY` | Coupe l'envoi de télémétrie anonyme. N'importe quelle valeur non vide active la désactivation. |
| `DISABLE_ERROR_REPORTING` | Coupe l'envoi de rapports d'erreur. N'importe quelle valeur non vide active la désactivation. |
| `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` | Coupe le trafic réseau non essentiel de Claude Code. N'importe quelle valeur non vide active la désactivation. |

::tip
Pour les variables « booléennes » comme `DISABLE_TELEMETRY`, mets `1` ou `true` pour activer, `0` ou `false` pour désactiver (la casse n'a pas d'importance). Certaines variables listées ci-dessus, dites « presence-based », s'activent dès qu'on leur donne n'importe quelle valeur non vide.
::
