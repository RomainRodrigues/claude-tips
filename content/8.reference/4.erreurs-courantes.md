Quand quelque chose ne va pas, commence toujours par lancer `/doctor` dans une session (diagnostic complet, propose des corrections) ou `claude doctor` depuis ton terminal si `claude` ne démarre même pas. Cette page couvre les erreurs et blocages les plus courants une fois Claude Code lancé — liste non exhaustive, voir les liens en bas de page pour le détail complet.

## Erreurs liées à l'API et à l'authentification

| Message / symptôme | Cause | Solution |
| --- | --- | --- |
| `API Error: 529 Overloaded` | Les serveurs d'Anthropic sont temporairement surchargés | Réessaie après quelques instants ; évite les heures de forte affluence si ça persiste |
| `API Error: 401` / clé API invalide | Tes identifiants sont refusés par l'API | Vérifie ta clé API, ou relance `/login` |
| Session non connectée / « Not logged in » | Aucune authentification valide trouvée | Lance `/login` |
| `429` / limitation de débit | Trop de requêtes envoyées en peu de temps | Attends avant de réessayer (backoff) |
| Solde de crédits insuffisant | Ton compte API n'a plus de crédits | Ajoute des crédits sur ta Console Anthropic |
| Erreur liée au modèle sélectionné / « model not found » | Le modèle demandé n'existe pas ou n'est pas accessible avec ton plan | Vérifie le nom du modèle et les modèles disponibles pour ton plan avec `/model` |

## Contexte et performance

| Symptôme | Cause | Solution |
| --- | --- | --- |
| `Autocompact is thrashing: the context refilled to the limit...` | La compaction automatique a réussi, mais un fichier ou une sortie d'outil a immédiatement rempli le contexte à nouveau, plusieurs fois de suite | Demande à Claude de lire le gros fichier par morceaux, lance `/compact` avec une consigne précise (ex. `/compact garde seulement le plan et le diff`), délègue le travail à un subagent, ou fais `/clear` si la conversation précédente n'est plus utile |
| `/compact` répond « Not enough messages to compact. » | La conversation a trop peu de tours pour être résumée, même si le contexte est plein (ça arrive avec un gros collage unique) | Continue la conversation normalement, ou fais `/clear` pour repartir de zéro |
| Un tableau Markdown est coupé dans le terminal (« … N more rows not shown ») | Un tableau de plus de 200 lignes n'affiche que les 200 premières à l'écran | Le tableau complet reste dans la conversation : `/copy` copie toutes les lignes, ou demande à Claude d'écrire le tableau dans un fichier |
| Utilisation CPU/mémoire élevée, lenteurs | Traitement d'un gros codebase, ou une extension/MCP/hook qui consomme trop | Lance `/compact` régulièrement, redémarre entre deux grosses tâches, ou relance avec `claude --safe-mode` pour voir si une personnalisation est en cause |
| Claude Code ne répond plus / semble figé | Blocage ponctuel | `Ctrl+C` pour annuler l'opération en cours ; si ça ne suffit pas, ferme le terminal et relance `claude --resume` dans le même dossier (rien n'est perdu) |

## Recherche de fichiers

| Symptôme | Cause | Solution |
| --- | --- | --- |
| L'outil de recherche, les mentions `@fichier`, ou les skills/agents personnalisés ne trouvent pas certains fichiers | Le binaire `ripgrep` fourni avec Claude Code ne fonctionne pas sur ton système | Installe `ripgrep` pour ton système (`brew install ripgrep`, `sudo apt install ripgrep`...), puis mets la variable d'environnement `USE_BUILTIN_RIPGREP` à `0` |
| Moins de résultats que prévu sous WSL | Pénalité de performance disque quand le projet est sur le système de fichiers Windows (`/mnt/c/...`) | Déplace ton projet vers le système de fichiers Linux (`/home/...`), ou utilise des recherches plus précises (dossier/type de fichier ciblé) |

## Configuration qui ne s'applique pas (settings, hooks, MCP)

| Symptôme | Cause | Solution |
| --- | --- | --- |
| Un hook ne se déclenche jamais | Le champ `matcher` est un tableau JSON au lieu d'une chaîne, ou utilise une virgule sur une version ancienne de Claude Code, ou le nom d'outil est mal écrit (la casse compte : `Bash`, pas `bash`) | Utilise une seule chaîne avec `\|` pour matcher plusieurs outils, par exemple `"Edit\|Write"` ; vérifie l'orthographe exacte du nom d'outil |
| Une valeur de `settings.json` semble ignorée | La même clé est aussi définie dans `settings.local.json`, qui a priorité | Vérifie `settings.local.json` : il surcharge `settings.json`, qui surcharge lui-même `~/.claude/settings.json` |
| Un serveur MCP apparaît connecté mais liste zéro outil | Le serveur a démarré mais ne renvoie pas de liste d'outils | Choisis « Reconnect » depuis `/mcp` ; si ça persiste, relance avec `claude --debug=mcp` et regarde le log dans `~/.claude/debug/<session-id>.txt` |
| Un serveur MCP ajouté au projet n'apparaît jamais | L'invite d'approbation ponctuelle a été fermée sans validation | Lance `/mcp` pour voir le statut et approuver le serveur |
| Des permissions, hooks ou variables `env` définis « globalement » sont ignorés | La configuration a été ajoutée dans `~/.claude.json` au lieu de `~/.claude/settings.json` | `~/.claude.json` ne contient que l'état de l'appli ; mets `permissions`, `hooks` et `env` dans `~/.claude/settings.json` |

::tip
**Pour aller plus loin dans le diagnostic** : `/context` montre tout ce qui occupe la fenêtre de contexte (y compris si un `CLAUDE.md` ou un skill a bien chargé), `/status` montre les sources de settings actives, et `claude --safe-mode` démarre une session avec toutes les personnalisations désactivées pour isoler la cause d'un problème.
::
