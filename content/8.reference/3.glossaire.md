Claude Code a son propre vocabulaire (session, hook, skill, subagent...). Cette page reprend les termes les plus utiles à connaître, avec une définition courte. Liste non exhaustive — la doc officielle en couvre davantage (notamment les termes liés au cloud, aux équipes d'agents et à l'administration).

## A

::field-group
  :::field{name="Agentic loop"}
  Le cycle que Claude répète pour chaque tâche : rassembler du contexte, agir, vérifier le résultat, recommencer jusqu'à ce que ce soit fini. Tu peux interrompre ce cycle à tout moment pour rediriger Claude.
  :::
  :::field{name="AGENTS.md"}
  Un fichier markdown d'instructions pour agents IA, utilisé par plusieurs outils (pas que Claude Code). Si ton dépôt en a un et pas de `CLAUDE.md`, Claude le lit comme instructions de projet.
  :::
  :::field{name="Auto mode"}
  Un mode de permission où un modèle classificateur (et non toi) approuve la plupart des actions à ta place, en te demandant confirmation seulement pour les cas qui matchent tes règles explicites. C'est le mode de départ par défaut des sessions interactives sur les plans Pro, Max et Team.
  :::
::

## B

::field-group
  :::field{name="Bare mode"}
  Avec le flag `--bare`, Claude Code démarre sans charger les hooks, skills, commandes personnalisées, subagents, plugins, serveurs MCP, mémoire auto ni `CLAUDE.md`. Utile pour la CI et les scripts qui doivent avoir un résultat identique sur toutes les machines.
  :::
::

## C

::field-group
  :::field{name="Checkpoint"}
  Un point de restauration créé à chaque message que tu envoies. Appuie deux fois sur `Escape` ou lance `/rewind` pour revenir en arrière (code, conversation, ou les deux). Différent de Git : les checkpoints ne suivent pas les changements faits via l'outil Bash.
  :::
  :::field{name="Dossier .claude"}
  Le dossier où Claude Code lit la configuration propre à un projet : settings, hooks, skills, subagents, règles, mémoire auto. Un projet a `.claude/` à sa racine ; tes réglages par défaut à toi sont dans `~/.claude/`.
  :::
  :::field{name="CLAUDE.md"}
  Un fichier markdown d'instructions persistantes que tu écris pour Claude, chargé au début de chaque session. C'est là que tu mets les conventions du projet, l'architecture, les règles du type « fais toujours X ». Il survit à la compaction et est relu depuis le disque après.
  :::
  :::field{name="Commande (slash command)"}
  Une instruction réutilisable que tu invoques en tapant `/nom` dans le prompt. Les commandes intégrées (`/clear`, `/model`, `/compact`...) contrôlent la session ; tu peux aussi en définir toi-même dans `.claude/commands/`. Les skills sont la façon recommandée de packager des commandes multi-étapes.
  :::
  :::field{name="Compaction"}
  Le résumé automatique de ta conversation quand la fenêtre de contexte approche de sa limite. Les résultats d'outils les plus anciens sont effacés en premier, puis la conversation est résumée. `CLAUDE.md` (à la racine du projet) et la mémoire auto survivent à la compaction.
  :::
  :::field{name="Fenêtre de contexte (context window)"}
  La mémoire de travail d'une session : historique de conversation, contenu des fichiers, sorties de commandes, `CLAUDE.md`, mémoire auto, skills chargés, instructions système. Lance `/context` pour voir ce qui occupe cet espace.
  :::
::

## H

::field-group
  :::field{name="Hook"}
  Un handler défini par toi qui s'exécute automatiquement à un moment précis du cycle de vie de Claude Code (avant qu'un outil s'exécute, après une modification de fichier, au démarrage d'une session...). Un hook est déterministe : il se déclenche à un point fixe, pas selon le jugement du modèle.
  :::
::

## M

::field-group
  :::field{name="MCP (Model Context Protocol)"}
  Un standard ouvert pour connecter des outils IA à des sources de données et services externes. Les serveurs MCP donnent à Claude de nouveaux outils (Slack, Jira, bases de données, navigateur...). Tu connectes des serveurs via `/mcp` ou en les ajoutant à `.mcp.json`.
  :::
  :::field{name="Serveur MCP"}
  Un programme qui fournit des outils, prompts ou ressources à Claude via MCP. Tu l'ajoutes avec `claude mcp add`, dans `.mcp.json`, via un plugin, ou comme connecteur claude.ai.
  :::
  :::field{name="Managed settings (settings gérés)"}
  Des settings imposés à l'échelle de toute une organisation par l'équipe IT/DevOps, livrés depuis les serveurs d'Anthropic ou déployés au niveau du système. Les settings utilisateur et projet ne peuvent pas les surcharger.
  :::
::

## N

::field-group
  :::field{name="Mode non-interactif (headless)"}
  Un mode qui exécute un seul prompt et quitte sans ouvrir de session interactive, invoqué avec `-p` ou `--print`. Utilisé pour la CI, les scripts et les pipes. Anciennement appelé « mode headless ».
  :::
::

## P

::field-group
  :::field{name="Mode de permission (permission mode)"}
  Le comportement d'approbation de base pour la session. Change de mode avec `Shift+Tab`. Les modes disponibles sont `default`, `acceptEdits`, `plan`, `auto`, `dontAsk` et `bypassPermissions`.
  :::
  :::field{name="Règle de permission"}
  Une entrée de settings qui autorise, questionne, ou refuse l'appel d'un outil selon son nom et un motif d'arguments. Les règles sont évaluées dans l'ordre refus → question → autorisation, et la première qui correspond gagne.
  :::
  :::field{name="Plan mode"}
  Un mode de permission où Claude recherche et propose des changements sans jamais modifier tes fichiers sources. Il peut lire, chercher, exécuter des commandes d'exploration, puis présente un plan à valider avant de toucher à quoi que ce soit.
  :::
  :::field{name="Plugin"}
  Un lot de skills, hooks, subagents et serveurs MCP packagés comme une seule unité installable. Les skills d'un plugin sont préfixés par `nom-du-plugin:` pour que plusieurs plugins cohabitent sans collision de noms.
  :::
::

## S

::field-group
  :::field{name="Sandboxing"}
  Isolation au niveau du système d'exploitation (fichiers et réseau) pour l'outil Bash. Les commandes tournent à l'intérieur d'une limite définie à l'avance, ce qui permet à Claude de travailler librement dedans sans invite de permission à chaque commande.
  :::
  :::field{name="Session"}
  Une conversation liée à ton dossier courant, avec sa propre fenêtre de contexte indépendante. Une session peut être reprise (`claude -c`), forkée (`--fork-session`), ou tourner en parallèle dans d'autres terminaux.
  :::
  :::field{name="Settings layers (couches de settings)"}
  La hiérarchie dans laquelle Claude Code lit sa configuration, par ordre de priorité décroissant : settings gérés (managed), arguments en ligne de commande, `.claude/settings.local.json`, `.claude/settings.json`, puis `~/.claude/settings.json`.
  :::
  :::field{name="Skill"}
  Un fichier `SKILL.md` qui contient des instructions, des connaissances ou un workflow que Claude ajoute à sa boîte à outils. Claude charge un skill automatiquement quand c'est pertinent, ou tu l'invoques directement avec `/nom-du-skill`. Successeur recommandé des commandes personnalisées.
  :::
  :::field{name="Subagent"}
  Un assistant IA spécialisé qui tourne dans sa propre fenêtre de contexte, avec un system prompt personnalisé, un accès aux outils spécifique et des permissions indépendantes. Il travaille sur une tâche déléguée et renvoie un résumé à la conversation principale.
  :::
::

## T

::field-group
  :::field{name="Tool (outil)"}
  Une action que Claude peut effectuer : lire un fichier, modifier du code, lancer une commande shell, chercher sur le web, déléguer à un subagent. Sans outils, Claude ne pourrait que répondre par du texte.
  :::
  :::field{name="Turn (tour)"}
  Une réponse complète de Claude au sein d'une session. Un tour commence quand tu envoies un message et se termine quand Claude a fini de répondre, avec un nombre quelconque d'appels d'outils entre les deux.
  :::
::

## W

::field-group
  :::field{name="Worktree isolation"}
  Un mode d'isolation qui fait tourner Claude dans un « worktree » Git séparé, sous `.claude/worktrees/`, activé avec le flag `-w`. Les changements restent sur une branche et dans un dossier séparés, pour que des agents en parallèle ne s'écrasent pas les fichiers les uns des autres.
  :::
::
