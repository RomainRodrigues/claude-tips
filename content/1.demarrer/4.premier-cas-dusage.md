Cette page reprend le déroulé du quickstart officiel : une suite de petites actions concrètes à essayer dans un vrai projet, pour prendre tes marques avant de creuser les fonctionnalités avancées.

## Quand l'utiliser

Juste après l'installation et la connexion, avant de lire le reste du site : c'est la meilleure façon de comprendre comment Claude Code travaille, en le voyant faire plutôt qu'en lisant de la théorie.

## Exemple minimal

Ouvre un terminal dans un projet existant et pose une question simple :

```bash [Terminal]
cd mon-projet
claude
```

```text [Dans la session Claude Code]
qu'est-ce que fait ce projet ?
```

## Exemple réaliste

Voici une progression complète à essayer, dans l'ordre :

::steps{level="3"}
### Comprendre le projet
```text [Dans la session Claude Code]
quelles technologies utilise ce projet ?
```
```text [Dans la session Claude Code]
où se trouve le point d'entrée principal ?
```
Claude Code lit tes fichiers au fur et à mesure, tu n'as rien à lui donner en contexte manuellement.

### Faire une première modification
```text [Dans la session Claude Code]
ajoute une fonction hello world dans le fichier principal
```
Claude Code trouve le bon fichier et te montre le changement proposé. S'il te demande une confirmation, choisis **Yes** pour l'accepter.

### Utiliser Git en langage naturel
```text [Dans la session Claude Code]
quels fichiers ai-je modifiés ?
```
```text [Dans la session Claude Code]
commit mes changements avec un message descriptif
```

### Corriger un vrai bug ou ajouter une fonctionnalité
```text [Dans la session Claude Code]
il y a un bug : les utilisateurs peuvent soumettre des formulaires vides - corrige ça
```
Claude Code localise le code concerné, comprend le contexte, implémente une solution et relance les tests s'il y en a.
::

## Pièges fréquents

::caution
**Sur les plans Pro/Max/Team, Claude peut déjà être en train d'agir sans te demander.** Le mode de permission de départ pour une session de terminal interactive est le « mode auto » : un classificateur relit les actions à ta place et laisse Claude modifier des fichiers et lancer des commandes sans confirmation à chaque fois. Appuie sur `Shift+Tab` pour passer à un mode où Claude demande avant chaque changement — voir [les modes de permission](/usage-quotidien/modes-de-permission).
::

::tip
**Sois spécifique plutôt que vague.** Au lieu de "corrige le bug", préfère "corrige le bug de connexion où les utilisateurs voient un écran blanc après un mauvais mot de passe". Plus le contexte est précis, moins Claude a besoin d'itérer pour comprendre ce que tu veux.
::

::note
**Tu n'as pas besoin d'un prompt parfait du premier coup.** Claude Code est conversationnel : commence par ce que tu veux, regarde ce qu'il fait, puis corrige-le en language naturel si ce n'est pas tout à fait ça. Pas besoin de repartir de zéro.
::
