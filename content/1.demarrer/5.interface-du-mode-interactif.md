Le mode interactif est l'écran que tu vois par défaut quand tu lances `claude` sans argument : une conversation dans ton terminal, avec quelques indicateurs et raccourcis à connaître pour t'y sentir à l'aise.

## Quand l'utiliser

Tout le temps — c'est le mode par défaut de Claude Code, celui que tu utilises dans 90% de tes sessions (à l'opposé du [mode headless](/automatiser/mode-headless-et-scripts) utilisé pour scripter).

## Exemple minimal

Trois caractères à connaître dès le départ :

```text [Dans la session Claude Code]
/
```
Tapé en début de message, affiche la liste des commandes et skills disponibles.

```text [Dans la session Claude Code]
@
```
Déclenche l'autocomplétion de chemin de fichier, pour mentionner précisément un fichier de ton projet dans ta question.

```text [Dans la session Claude Code]
!
```
Tapé en début de message, passe en **mode shell** : ce qui suit est lancé directement dans ton terminal, sans passer par Claude.

## Exemple réaliste

Une session type ressemble à ceci :

::steps{level="3"}
### Repérer les indicateurs
Au-dessus de la zone de saisie, Claude Code affiche la version, le modèle utilisé, le dossier courant et le mode de permission actif (Manual, Accept edits, Plan, Auto...).

### Écrire une question multiligne
Pour un prompt sur plusieurs lignes, termine chaque ligne par `\` puis `Entrée` (fonctionne dans tous les terminaux), ou utilise `Shift+Entrée` si ton terminal le supporte nativement.

### Mentionner un fichier précis
```text [Dans la session Claude Code]
explique-moi la logique dans @src/auth/login.ts
```

### Lancer une commande sans passer par Claude
```text [Dans la session Claude Code]
! npm test
```
La commande s'exécute directement, sans que Claude ait besoin de l'interpréter ou de l'approuver. Sa sortie est ajoutée à la conversation, et Claude répond automatiquement dessus — pratique pour lancer `! npm test` et obtenir directement une explication des échecs, sans avoir à recopier la sortie toi-même. Sors du mode shell avec `Echap`, `Retour arrière` ou `Ctrl+U` sur un prompt vide.

### Interrompre si besoin
Appuie sur `Esc` à tout moment pour arrêter Claude en plein milieu d'une action et le rediriger, sans perdre le travail déjà fait.

### Changer de mode de permission
Appuie sur `Shift+Tab` pour faire défiler les modes de permission disponibles (voir [les modes de permission](/usage-quotidien/modes-de-permission) pour le détail de chacun).
::

## Pièges fréquents

::warning
**`Esc` deux fois sur un champ vide n'efface pas juste, ça ouvre le menu de rewind.** Si le champ de saisie est vide et que tu appuies deux fois sur `Esc`, Claude Code ouvre le menu pour revenir à un état précédent de la conversation ou du code — voir [checkpoints et rewind](/usage-quotidien/checkpoints-et-rewind). Si le champ contient du texte, ce même raccourci l'efface simplement (et le garde dans l'historique).
::

::note
**`Ctrl+C` ne quitte pas immédiatement.** Le premier appui interrompt l'action en cours ou vide le champ de saisie ; il faut appuyer une seconde fois pour quitter Claude Code. Pas de panique si rien ne se passe au premier essai.
::

::tip
**Sur macOS, certains raccourcis avec Option ne marchent pas par défaut.** Les raccourcis comme `Alt+B` (mot précédent) ou `Alt+D` (supprimer jusqu'à la fin du mot) nécessitent de configurer la touche Option comme Meta dans ton terminal — voir la doc officielle sur la configuration du terminal.
::

::caution
**Le mode shell (`!`) contourne le sandbox et les permissions.** Contrairement aux commandes que Claude lance lui-même, une commande tapée après `!` s'exécute directement sur ta machine, même si tu as activé le [sandboxing](https://code.claude.com/docs/en/sandboxing) — la sandbox ne s'applique qu'aux commandes que Claude décide de lancer, pas à celles que tu tapes toi-même. C'est toi qui es responsable de ce que tu tapes après `!`, exactement comme dans un terminal classique.
::

::note
**Chaque commande `!` déclenche une réponse de Claude, qui compte comme un message.** Si tu veux juste ajouter la sortie au contexte sans que Claude réponde à chaque fois, mets `respondToBashCommands` à `false` dans ton `settings.json`.
::
