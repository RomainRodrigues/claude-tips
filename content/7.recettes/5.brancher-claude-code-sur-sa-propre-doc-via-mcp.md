Copier-coller des extraits de documentation dans le prompt fonctionne, mais ça devient vite pénible et périmé. En exposant un site de doc comme serveur MCP, Claude Code peut interroger son contenu à jour directement pendant la conversation, comme un outil de recherche intégré.

## Prérequis

- Claude Code installé et authentifié.
- Un site de documentation qui expose un endpoint MCP en HTTP — soit un serveur tiers déjà existant, soit ta propre doc si elle utilise un module qui expose une route dédiée (le site claude-tips lui-même utilise `@nuxtjs/mcp-toolkit`, qui expose `/mcp`).

## Étapes

::steps{level="3"}
### Ajouter le serveur MCP

Depuis un terminal (pas depuis une session `claude` déjà ouverte), enregistre le serveur avec la commande `claude mcp add`. L'exemple ci-dessous utilise le serveur MCP officiel de la doc de Claude Code lui-même, qui ne demande aucune authentification :

```bash [Terminal]
claude mcp add --transport http claude-code-docs https://code.claude.com/docs/mcp
```

- `--transport http` : le serveur est hébergé à une URL, ce n'est pas un programme local.
- `claude-code-docs` : un nom que tu choisis toi-même, utilisé ensuite pour le retrouver (`claude mcp remove claude-code-docs`, par exemple).

### Vérifier que la connexion fonctionne

```bash [Terminal]
claude mcp list
```

Le serveur doit apparaître avec le statut `✔ Connected`. S'il affiche `! Needs authentication`, le serveur nécessite une connexion via navigateur (voir la variante plus bas).

### Utiliser le serveur dans une session

```bash [Terminal]
claude
```

```text [Dans la session Claude Code]
utilise le serveur claude-code-docs pour vérifier ce que fait la variable MCP_TIMEOUT
```

Tu n'as normalement pas besoin de nommer le serveur explicitement — Claude choisit lui-même les outils pertinents — mais le faire ici garantit que la réponse vient bien du serveur MCP et pas de la mémoire du modèle. Les appels d'outils dans la sortie de Claude sont étiquetés avec le nom du serveur, ce qui te permet de vérifier la source.

### Brancher ta propre documentation (une fois déployée)

Si ton site de doc expose lui-même une route MCP (comme `/mcp` avec `@nuxtjs/mcp-toolkit`), la commande est identique, avec ton propre domaine :

```bash [Terminal]
claude mcp add --transport http ma-doc https://mon-domaine.example/mcp
```

### Choisir la portée du serveur

Par défaut, `claude mcp add` enregistre le serveur en portée `local` (privé, uniquement dans ce projet). Pour le rendre disponible partout, ou le partager avec ton équipe :

:::code-group
```bash [Toutes tes sessions (user)]
claude mcp add --scope user --transport http claude-code-docs https://code.claude.com/docs/mcp
```

```bash [Partagé avec l'équipe (project)]
claude mcp add --scope project --transport http claude-code-docs https://code.claude.com/docs/mcp
```
:::

La portée `project` écrit dans un fichier `.mcp.json` à committer : tes coéquipiers qui clonent le dépôt reçoivent une demande d'approbation au premier lancement, puis le serveur se connecte pour eux aussi.

### Retirer le serveur si besoin

```bash [Terminal]
claude mcp remove claude-code-docs
```
::

## Résultat attendu

Le panneau `/mcp` d'une session liste le serveur avec un statut connecté et son nombre d'outils disponibles. Quand tu poses une question qui touche à la doc branchée, Claude Code appelle le serveur plutôt que de répondre depuis sa mémoire d'entraînement — ce qui est particulièrement utile pour une doc qui évolue vite ou qui documente ton propre produit.

::note
**Chaque serveur connecté prend de la place en contexte.** Les noms d'outils et les instructions du serveur se chargent dans chaque session. Retire les serveurs que tu n'utilises plus avec `claude mcp remove`.
::

## Variantes

Pour un serveur protégé par une connexion (OAuth), l'ajout se fait de la même façon mais le statut affiche `! Needs authentication` jusqu'à ce que tu lances `/mcp` dans une session, sélectionnes le serveur et choisisses **Authenticate** pour finir la connexion dans ton navigateur. Pour une doc qui vit uniquement en local (pas encore déployée), un serveur `stdio` (un programme lancé en local plutôt qu'une URL) peut convenir à la place d'un serveur HTTP.
