Plutôt que de relire chaque pull request soi-même, on peut brancher Claude Code sur GitHub Actions : dès qu'une PR est ouverte ou mise à jour, Claude la relit et poste ses remarques directement dessus.

## Prérequis

- Un dépôt hébergé sur **github.com**, avec un accès **admin** dessus.
- Le [GitHub CLI](https://cli.github.com) installé et authentifié (`gh auth login`).
- Claude Code installé et lancé en local (pour l'installation guidée) — ou, en manuel, un compte Claude Console (clé API) ou un abonnement Pro/Max/Team (token OAuth).

## Étapes

::steps{level="3"}
### Lancer l'installation guidée

Ouvre `claude` à la racine du dépôt que tu veux connecter, puis lance la commande d'installation.

```bash [Terminal]
cd mon-projet
claude
```

```text [Dans la session Claude Code]
/install-github-app
```

Claude Code installe l'application GitHub officielle sur le dépôt et enchaîne sur la configuration de l'authentification.

### Choisir comment Claude s'authentifie en CI

Deux options, selon ce que tu as déjà :

- Une **clé API** de la [Claude Console](https://platform.claude.com), stockée dans un secret `ANTHROPIC_API_KEY`.
- Un **token lié à ton abonnement** Claude (Pro, Max, Team), généré avec `claude setup-token`, stocké dans un secret `CLAUDE_CODE_OAUTH_TOKEN`.

Claude Code enregistre le secret choisi comme secret du dépôt automatiquement.

### Sélectionner le workflow de revue de PR

Dans les propositions de workflows, choisis celui de revue automatique. Claude Code pousse une branche contenant le fichier de workflow et ouvre dans ton navigateur une pull request prête à créer.

### Merger la pull request de configuration

Crée et merge cette pull request comme n'importe quelle autre. À partir de là, le workflow tourne sur chaque nouvelle PR du dépôt.

### Tester sur une vraie pull request

Ouvre ou mets à jour une pull request de test. Claude Code relit le diff et poste ses remarques en commentaires en ligne sur les problèmes trouvés, ou un seul commentaire récapitulatif s'il n'a rien à signaler.

:::note
Claude Code passe sciemment certaines PR : les brouillons (*draft*), celles qu'il juge ne pas avoir besoin de revue (automatisées, triviales), et celles où il a déjà laissé un commentaire.
:::
::

## Résultat attendu

Le fichier `.github/workflows/claude-code-review.yml` suivant (ou très proche) apparaît dans le dépôt après l'installation guidée, et se déclenche à chaque ouverture, mise à jour, sortie de brouillon ou réouverture de PR :

```yaml [.github/workflows/claude-code-review.yml]
name: Code Review
on:
  pull_request:
    types: [opened, synchronize, ready_for_review, reopened]
jobs:
  review:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pull-requests: read
      issues: read
      id-token: write
    steps:
      - uses: actions/checkout@v6
        with:
          fetch-depth: 1
      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
          plugin_marketplaces: "https://github.com/anthropics/claude-code.git"
          plugins: "code-review@claude-code-plugins"
          prompt: "/code-review:code-review --comment ${{ github.repository }}/pull/${{ github.event.pull_request.number }}"
          claude_args: '--allowedTools "mcp__github_inline_comment__create_inline_comment"'
```

::warning
**Ne commite jamais une clé API en dur.** Passe toujours par les secrets GitHub (`${{ secrets.ANTHROPIC_API_KEY }}`), jamais par une valeur écrite directement dans le workflow.
::

## Variantes

Pour répondre à Claude à la demande plutôt qu'automatiquement sur chaque PR, installe plutôt (ou en plus) le workflow classique qui réagit aux mentions `@claude` dans un commentaire d'issue ou de PR — c'est le premier workflow proposé par `/install-github-app`. Pour un rapport récurrent plutôt qu'une revue de PR, un workflow avec un déclencheur `schedule` (cron) et un `prompt` fixe fonctionne sur le même principe : voir l'exemple *Run on a schedule* de la doc officielle.

::tip
Si tu veux une revue automatique sans maintenir de fichier de workflow toi-même, regarde aussi [Code Review](https://code.claude.com/docs/en/code-review), un produit distinct qui active la revue automatique sur un dépôt sans configuration YAML.
::
