Un refactor important fait hésiter parce qu'il touche beaucoup de fichiers et qu'on n'est jamais sûr à 100 % de l'approche. Les checkpoints de Claude Code changent la donne : chaque prompt qui démarre un tour de conversation sauvegarde l'état du code, donc tu peux tenter une approche risquée et revenir en arrière en deux touches si ça ne va pas.

## Prérequis

- Une session interactive Claude Code (les checkpoints sont une fonctionnalité du mode interactif, pas du mode `-p`).
- Idéalement, un dépôt git avec l'état de départ committé — les checkpoints sont un filet de sécurité pratique pour la session en cours, pas un remplaçant de git.

## Étapes

::steps{level="3"}
### Partir d'un état propre

Vérifie qu'il n'y a rien en attente avant de commencer, pour pouvoir comparer facilement plus tard si besoin.

```bash [Terminal]
git status
```

### Lancer le refactor sans trop de prudence

Décris le refactor voulu et laisse Claude avancer. Comme chaque prompt crée un checkpoint, tu peux te permettre une approche ambitieuse plutôt que de tout découper en micro-étapes validées une par une.

```text [Dans la session Claude Code]
refactorise utils.js pour utiliser les fonctionnalités modernes de JavaScript (ES2024), en gardant exactement le même comportement
```

### Vérifier le résultat

```text [Dans la session Claude Code]
lance les tests pour vérifier que le comportement n'a pas changé
```

### Si ça part dans le mauvais sens, ouvrir le menu de rewind

Appuie deux fois sur `Échap` (quand le champ de saisie est vide), ou tape `/rewind`.

```text [Dans la session Claude Code]
/rewind
```

Choisis le message correspondant au point de départ du refactor, puis l'action voulue :

- **Restaurer le code et la conversation** : tout revient à cet instant, comme si le refactor n'avait jamais eu lieu.
- **Restaurer le code** : les fichiers reviennent en arrière, mais la conversation (et ce que Claude a appris en explorant) reste.
- **Restaurer la conversation** : le fil de discussion revient en arrière, mais le code reste tel quel — utile si tu veux reformuler ta demande sans perdre les fichiers déjà modifiés.

### Retenter une autre approche

Le prompt d'origine est replacé dans le champ de saisie après une restauration : modifie-le pour orienter Claude différemment avant de renvoyer.

```text [Dans la session Claude Code]
refactorise utils.js en gardant les fonctions séparées par domaine plutôt qu'en un seul module
```
::

## Résultat attendu

Tu peux annuler n'importe quelle passe de refactor ratée en quelques secondes, sans perdre toute la conversation ni devoir tout committer/annuler côté git à chaque tentative. Le menu `/rewind` te montre l'historique des prompts de la session et te laisse choisir précisément jusqu'où revenir.

::warning
**Les checkpoints ne suivent pas tout.** Ils ne capturent que les fichiers modifiés par les outils d'édition de Claude. Les changements faits via une commande Bash (`rm`, `mv`, un script qui écrit des fichiers) ou par un subagent qui tourne en arrière-plan ne sont pas restaurés par `/rewind`. Pour ces cas-là, seul git peut t'aider — d'où l'intérêt de partir d'un état committé.
::

::note
**Ce n'est pas un remplaçant de git.** Claude Code garde les snapshots des 100 checkpoints les plus récents d'une session, et les supprime définitivement au bout d'environ 30 jours sans activité sur la session (réglable via `cleanupPeriodDays`). Pour un historique permanent et du travail en équipe, continue à committer normalement.
::

## Variantes

Si le refactor est surtout long à discuter plutôt qu'à risque, utilise **Summarize from here** / **Summarize up to here** depuis le menu `/rewind` pour compresser une partie de la conversation et libérer du contexte sans perdre les décisions prises. Pour comparer deux approches de refactor en parallèle sans jongler avec le rewind, lance plutôt deux sessions dans des [worktrees](https://code.claude.com/docs/en/worktrees) git séparés.
