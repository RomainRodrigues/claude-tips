Une commande personnalisée, c'est un fichier que tu écris une fois et qui devient une commande `/nom-de-commande` : tu la tapes dans la session, et Claude reçoit tes instructions toutes prêtes, sans que tu aies à les retaper à chaque fois.

::note
Techniquement, une commande personnalisée est une **skill** (un fichier `SKILL.md`) : c'est le même mécanisme, vu ici sous son angle le plus simple. La page suivante, [Skills](/etendre/skills), va plus loin (plusieurs fichiers, exécution isolée, permissions fines...).
::

## Quand l'utiliser

Dès que tu te surprends à copier-coller le même genre de message à Claude : résumer le diff avant un commit, remplir un rapport de bug, appliquer une checklist de relecture... Une commande perso évite le copier-coller, et peut même aller chercher elle-même des informations à jour (comme le résultat d'une commande Git) avant que Claude ne les lise.

## Exemple minimal

Crée un dossier `resume-diff/` avec un fichier `SKILL.md` dedans. Le nom du dossier devient le nom de la commande.

```markdown [~/.claude/skills/resume-diff/SKILL.md]
---
description: Résume les changements non commités et signale les points risqués
---

## Changements actuels

!`git diff HEAD`

## Instructions

Résume les changements ci-dessus en deux ou trois puces, puis liste les risques éventuels (gestion d'erreurs manquante, valeurs codées en dur, tests à mettre à jour). Si le diff est vide, dis-le simplement.
```

La ligne qui commence par `` !` `` est exécutée par Claude Code **avant** que le contenu soit envoyé à Claude : le texte `` !`git diff HEAD` `` est remplacé par le résultat réel de la commande. Claude ne voit jamais la commande elle-même, seulement sa sortie.

Une fois le fichier en place, tape simplement dans une session :

```text [Dans la session Claude Code]
/resume-diff
```

## Exemple réaliste

Une commande plus poussée, pensée pour un vrai usage : elle prépare un commit à partir des changements en cours, avec des outils pré-autorisés pour ne pas être interrompue par des demandes de permission.

```markdown [.claude/skills/commit/SKILL.md]
---
description: Prépare et crée un commit à partir des changements en cours
disable-model-invocation: true
allowed-tools: Bash(git add *) Bash(git commit *) Bash(git status *)
---

## État actuel

!`git status --short`

## Diff

!`git diff HEAD`

## Instructions

Écris un message de commit clair en français à partir du diff ci-dessus, en respectant les conventions du projet (ni trop court, ni un roman). Puis exécute `git add` sur les fichiers concernés et crée le commit.
```

Points à noter dans cet exemple :

- `disable-model-invocation: true` empêche Claude de lancer cette commande tout seul (un commit a un effet de bord réel) : seul toi peux taper `/commit`.
- `allowed-tools` pré-autorise uniquement `git add`, `git commit` et `git status` — Claude n'aura pas besoin de te demander la permission pour ces commandes précises pendant ce tour.

Invocation :

```text [Dans la session Claude Code]
/commit
```

## Pièges fréquents

::warning
**Le nom du dossier fixe le nom de la commande.** Renommer `resume-diff/` renomme aussi `/resume-diff`. Si tu ranges une commande dans un sous-dossier imbriqué, son nom se préfixe automatiquement avec le chemin (par exemple une commande dans `apps/web/.claude/skills/deploy/` peut devenir `/apps/web:deploy` si une autre commande `/deploy` existe déjà à la racine).
::

::warning
**`allowed-tools` ne dure qu'un seul tour.** La permission accordée par une commande s'efface dès ton message suivant — elle ne rend pas ces outils autorisés pour le reste de la session.
::

::caution
**Une commande `!` qui échoue bloque toute l'invocation.** Si la commande shell derrière un `` !`...` `` renvoie une erreur, Claude ne voit rien du tout — l'exécution de la skill s'arrête net. Ajoute `|| true` à la fin d'une commande qui peut légitimement échouer (par exemple `git diff HEAD || true` sur un tout premier commit sans historique).
::

::note
**Tu croiseras peut-être `.claude/commands/nom.md`** dans d'anciens tutoriels ou projets : c'est l'ancien mécanisme, un simple fichier `.md` sans dossier dédié. Il fonctionne encore mais est déprécié au profit des skills (dossier + `SKILL.md`) décrites ci-dessus.
::
