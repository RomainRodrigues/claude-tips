Un hook est une commande shell que tu programmes pour qu'elle s'exécute automatiquement à un moment précis de la session (avant un outil, après une modification, à la fin d'une réponse...) — un moyen fiable d'imposer une règle ou d'automatiser une tâche sans dépendre du bon vouloir du modèle.

## Quand l'utiliser

Pour des règles non négociables (interdire de toucher à `.env`, bloquer une commande dangereuse) que tu ne veux pas laisser à l'appréciation du modèle, ou pour automatiser une tâche répétitive (formater un fichier après chaque édition, recevoir une notification desktop quand Claude attend une réponse, journaliser les commandes exécutées).

## Exemple minimal

Une notification sur ton bureau chaque fois que Claude attend ton input, pour ne plus avoir à surveiller le terminal. Ajoute ceci à `~/.claude/settings.json` :

::code-group
```json [macOS]
{
  "hooks": {
    "Notification": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "osascript -e 'display notification \"Claude Code needs your attention\" with title \"Claude Code\"'"
          }
        ]
      }
    ]
  }
}
```

```json [Linux]
{
  "hooks": {
    "Notification": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "notify-send 'Claude Code' 'Claude Code needs your attention'"
          }
        ]
      }
    ]
  }
}
```

```json [Windows (PowerShell)]
{
  "hooks": {
    "Notification": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "powershell.exe -Command \"[System.Reflection.Assembly]::LoadWithPartialName('System.Windows.Forms'); [System.Windows.Forms.MessageBox]::Show('Claude Code needs your attention', 'Claude Code')\""
          }
        ]
      }
    ]
  }
}
```
::

Tape `/hooks` dans une session pour vérifier que ton hook apparaît bien dans la liste (ce menu est en lecture seule : pour modifier un hook, édite le fichier de settings ou demande à Claude de le faire).

## Exemple réaliste

Empêcher Claude de modifier des fichiers sensibles (`.env`, `package-lock.json`, tout ce qui est dans `.git/`), avec un message d'explication renvoyé à Claude s'il essaie quand même.

::steps{level="3"}
### Créer le script du hook

```bash [.claude/hooks/protect-files.sh]
#!/bin/bash
INPUT=$(cat)
FILE_PATH=$(echo "$INPUT" | jq -r '.tool_input.file_path // empty')

PROTECTED_PATTERNS=(".env" "package-lock.json" ".git/")

for pattern in "${PROTECTED_PATTERNS[@]}"; do
  if [[ "$FILE_PATH" == *"$pattern"* ]]; then
    echo "Bloqué : $FILE_PATH correspond au motif protégé '$pattern'" >&2
    exit 2
  fi
done

exit 0
```

### Rendre le script exécutable

```bash [Terminal]
chmod +x .claude/hooks/protect-files.sh
```

### Enregistrer le hook

```json [.claude/settings.json]
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/protect-files.sh"
          }
        ]
      }
    ]
  }
}
```

### Tester

Demande à Claude d'ajouter un commentaire dans ton fichier `.env`. Claude Code bloque l'édition avant qu'elle ne s'exécute, et transmet le message `Bloqué : ...` à Claude pour qu'il ajuste son approche.
::

## Pièges fréquents

::warning
**Code de sortie `0` ne veut pas dire « autorisé ».** Pour un hook `PreToolUse`, sortir avec le code `0` signifie juste « pas d'avis » — le circuit de permission normal continue à s'appliquer. Seul le code `2` bloque explicitement l'action (avec le message d'erreur envoyé sur `stderr`).
::

::warning
**Un script non exécutable échoue silencieusement.** Après avoir créé un script de hook, pense à `chmod +x` — sinon Claude Code ne peut pas le lancer et tu obtiens une erreur du type « command not found » dans le hook.
::

::caution
**Un champ JSON mal placé est ignoré sans erreur visible.** Par exemple, `permissionDecision` doit être imbriqué dans `hookSpecificOutput` — placé à la racine du JSON, Claude Code l'ignore silencieusement (visible uniquement dans les logs de debug avec `claude --debug`).
::

::note
**Un `matcher` vide (`""`) se déclenche sur tout.** C'est pratique pour un hook `Notification` général, mais dangereux pour un hook qui approuve automatiquement des permissions : garde le `matcher` le plus étroit possible (par exemple `ExitPlanMode` plutôt que `.*`) pour ne pas approuver silencieusement des actions que tu n'as pas voulu autoriser.
::
