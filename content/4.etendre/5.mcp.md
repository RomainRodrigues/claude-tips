MCP (Model Context Protocol) est un standard ouvert qui permet de brancher des outils externes à Claude Code — une base de données, un tracker comme Jira, un navigateur — sous forme de « serveurs MCP » que Claude peut ensuite utiliser comme des outils normaux.

## Quand l'utiliser

Dès qu'une tâche demande d'aller chercher ou modifier des informations dans un service que Claude ne peut pas atteindre nativement : consulter une base de données, créer une issue GitHub, piloter un navigateur pour tester une page, interroger un outil de monitoring comme Sentry.

## Exemple minimal

Le serveur de documentation officiel de Claude Code est un bon premier essai : hébergé, sans authentification.

```bash [Terminal]
claude mcp add --transport http claude-code-docs https://code.claude.com/docs/mcp
```

Vérifie que la connexion fonctionne :

```bash [Terminal]
claude mcp list
```

Tu dois voir `✔ Connected` en face du serveur. Démarre ensuite une session et demande à Claude de l'utiliser :

```text [Dans la session Claude Code]
Utilise le serveur claude-code-docs pour chercher ce que fait MCP_TIMEOUT
```

Cette commande enregistre le serveur en scope `local` : il n'est actif que dans ce projet précis, et seulement pour toi.

## Exemple réaliste

Donner à Claude un navigateur qu'il peut piloter, avec le serveur [Playwright MCP](https://github.com/microsoft/playwright-mcp) — utile pour vérifier qu'une page s'affiche encore correctement après une modification.

::steps{level="3"}
### Ajouter le serveur

```bash [Terminal]
claude mcp add playwright -- npx -y @playwright/mcp@latest
```

Tout ce qui suit le séparateur `--` est la commande que Claude Code lance pour démarrer le serveur. Comme il tourne en local (pas d'URL distante), pas besoin de `--transport` : `stdio` est la valeur par défaut.

### Vérifier la connexion

```bash [Terminal]
claude mcp list
```

Le premier essai peut afficher `✘ Failed to connect` le temps que `npx` télécharge le paquet — patiente un instant et relance la commande.

### Utiliser le navigateur

```text [Dans la session Claude Code]
Utilise playwright pour ouvrir https://example.com et donne-moi le titre de la page
```

Une fenêtre de navigateur s'ouvre pour que tu puisses suivre ce que fait Claude, et les appels d'outils dans sa réponse sont étiquetés avec le nom du serveur (`playwright`).
::

## Pièges fréquents

::note
**Le scope `local` est le défaut, et il n'est pas partagé.** `claude mcp add` sans option enregistre le serveur uniquement pour toi, uniquement dans ce projet. Ajoute `--scope user` pour l'avoir dans tous tes projets, ou `--scope project` pour l'écrire dans un fichier `.mcp.json` partagé avec ton équipe (à committer).
::

::warning
**Un serveur `.mcp.json` (scope project) demande une approbation avant de tourner.** C'est volontaire : un dépôt que tu clones ne doit pas pouvoir lancer un processus sur ta machine sans ton accord explicite. Si tu as refusé par erreur, `claude mcp reset-project-choices` réinitialise les choix d'approbation.
::

::caution
**Ne mets jamais de token en clair dans un `.mcp.json` committé.** Utilise plutôt l'expansion de variables d'environnement (`"Authorization": "Bearer ${API_KEY}"`) ou, pour des identifiants éphémères, un `headersHelper` — un script qui génère les en-têtes à la volée plutôt que de les stocker.
::

::note
**`Failed to connect` sur un serveur `stdio` local n'est pas toujours une vraie panne.** La première connexion peut échouer pendant que `npx` télécharge le paquet du serveur — relance `claude mcp list` après quelques secondes avant de chercher plus loin.
::
