Un subagent est un assistant Claude spécialisé que tu configures une fois dans un fichier : il a sa propre fenêtre de contexte, son propre jeu d'outils autorisés, et Claude Code peut lui déléguer une tâche précise pour garder ta conversation principale propre et concentrée.

## Quand l'utiliser

Quand une tâche mérite d'être isolée : une relecture de code en lecture seule, une recherche exploratoire qui produirait beaucoup de bruit dans le fil principal, une tâche que tu veux limiter à des outils précis (par exemple interdire toute écriture). C'est aussi utile pour paralléliser du travail sans polluer le contexte de la conversation en cours.

## Exemple minimal

Un subagent de relecture de code, en lecture seule :

```markdown [.claude/agents/code-reviewer.md]
---
name: code-reviewer
description: Relit le code pour la qualité et les bonnes pratiques. À utiliser après une modification de code.
tools: Read, Glob, Grep
model: sonnet
---

Tu es un relecteur de code. Quand on t'invoque, analyse le code et donne un
retour concret et actionnable sur la qualité, la sécurité et les bonnes
pratiques.
```

Claude peut le déléguer automatiquement si ta demande correspond à sa `description`, ou tu peux l'appeler explicitement :

```text [Dans la session Claude Code]
Utilise le subagent code-reviewer pour relire mes derniers changements
```

Pour être sûr qu'un subagent précis est bien utilisé (et pas un autre), tape `@` et sélectionne-le dans la liste, ou écris directement `@agent-code-reviewer`.

## Exemple réaliste

Un subagent qui interroge une base de données en lecture seule, avec un hook qui bloque toute requête d'écriture même si le modèle se trompe :

```yaml [.claude/agents/db-reader.md]
---
name: db-reader
description: Exécute des requêtes de lecture seule sur la base de données
tools: Bash
hooks:
  PreToolUse:
    - matcher: "Bash"
      hooks:
        - type: command
          command: "./scripts/validate-readonly-query.sh"
---

Tu es un analyste de données. Exécute des requêtes SELECT pour analyser les
données. N'exécute jamais de requête qui modifie la base.
```

Le script appelé par le hook lit la commande proposée et bloque tout ce qui ressemble à une écriture :

```bash [scripts/validate-readonly-query.sh]
#!/bin/bash
INPUT=$(cat)
COMMAND=$(echo "$INPUT" | jq -r '.tool_input.command // empty')

# Bloque les opérations d'écriture SQL (insensible à la casse)
if echo "$COMMAND" | grep -iE '\b(INSERT|UPDATE|DELETE|DROP|CREATE|ALTER|TRUNCATE)\b' > /dev/null; then
  echo "Bloqué : seules les requêtes SELECT sont autorisées" >&2
  exit 2
fi

exit 0
```

```bash [Terminal]
chmod +x ./scripts/validate-readonly-query.sh
```

Ici, la restriction ne repose pas seulement sur la description du subagent ou sa bonne volonté : le hook l'applique de façon systématique, quoi qu'il arrive.

## Pièges fréquents

::warning
**Sans le champ `tools`, le subagent hérite de tous les outils disponibles.** Beaucoup de débutants pensent qu'un subagent est restreint par défaut — c'est l'inverse : si tu veux un subagent en lecture seule, tu dois lister explicitement les outils autorisés (`tools: Read, Grep, Glob`) ou utiliser `disallowedTools` pour retirer ce que tu ne veux pas.
::

::warning
**Garde les descriptions courtes.** Claude Code décide de déléguer automatiquement en comparant ta demande aux champs `description` de tous les subagents disponibles — l'ensemble de ces descriptions ne doit pas dépasser 15 000 tokens. Mets le détail dans le corps du fichier (le prompt système), pas dans la description.
::

::caution
**Le même nom de subagent peut exister à plusieurs endroits.** Si tu as un `code-reviewer` à la fois dans `.claude/agents/` (projet) et `~/.claude/agents/` (personnel), c'est celui du projet qui l'emporte. L'ordre de priorité complet est : réglages managés par une organisation, puis flag `--agents` en ligne de commande, puis `.claude/agents/` (projet), puis `~/.claude/agents/` (personnel), puis les subagents fournis par des plugins.
::

::note
**Le modèle utilisé par un subagent se résout dans cet ordre** : le paramètre passé lors de l'invocation, puis le champ `model` du fichier du subagent, puis la variable d'environnement `CLAUDE_CODE_SUBAGENT_MODEL`, et enfin le modèle de la conversation principale si rien d'autre n'est précisé.
::
