La fenêtre de contexte, c'est toute la mémoire de travail de Claude pour la session en cours : ton fichier `CLAUDE.md`, chaque fichier lu, chaque commande lancée, chaque message échangé. Plus elle se remplit, plus les réponses de Claude peuvent se dégrader.

## Quand l'utiliser

Surveille et gère ton contexte dès qu'une session s'allonge : exploration d'un gros fichier, longue session de debug, ou changement de sujet en cours de route. Un contexte encombré par des informations qui n'ont plus d'utilité fait « oublier » à Claude des instructions données plus tôt.

::note
La taille par défaut de la fenêtre de contexte est de 200 000 tokens. Certains modèles (Sonnet 5, Opus 4.6 et plus, Sonnet 4.6, les modèles Fable) supportent une fenêtre étendue à 1 million de tokens.
::

## Exemple minimal

Pour voir ce qui remplit ton contexte à l'instant T :

```text [Dans la session Claude Code]
/context
```

Pour libérer de la place en résumant la conversation en cours :

```text [Dans la session Claude Code]
/compact
```

## Exemple réaliste

Une session de debug qui s'éternise, et comment la garder saine.

::steps{level="3"}
### Vérifier l'état du contexte

```text [Dans la session Claude Code]
/context
```

Affiche une grille colorée de ce qui occupe la fenêtre : `CLAUDE.md`, mémoire automatique, outils MCP, fichiers lus, historique de conversation.

### Résumer plutôt que tout effacer

Si la conversation devient longue mais que tu veux continuer sur le même sujet :

```text [Dans la session Claude Code]
/compact concentre-toi sur le bug d'authentification et les fichiers modifiés
```

`/compact` remplace l'historique par un résumé structuré, en gardant les fichiers modifiés récemment et les compétences (skills) que tu as invoquées. La conversation continue, mais avec beaucoup moins de tokens.

### Repartir de zéro entre deux tâches sans rapport

```text [Dans la session Claude Code]
/clear
```

Contrairement à `/compact`, `/clear` démarre une conversation entièrement vide. La conversation précédente n'est pas perdue : tu peux la retrouver avec `/resume`.

### Déléguer l'exploration à un subagent

Pour une recherche qui va lire beaucoup de fichiers sans que tu aies besoin du détail dans ta conversation principale :

```text [Dans la session Claude Code]
utilise un subagent pour explorer comment le système d'auth gère le refresh de token
```

Le subagent travaille dans sa propre fenêtre de contexte séparée ; seul son résumé final revient dans la tienne.
::

## Pièges fréquents

::warning
**Claude Code compacte automatiquement quand le contexte approche de la limite** — tu n'as donc pas besoin d'agir en urgence. Mais un `/compact` manuel avec des instructions ciblées (`/compact focus sur X`) donne un résumé plus pertinent que la passe automatique, qui devine ce qui compte.
::

::caution
**Les règles avec un `paths:` dans leur frontmatter, et les `CLAUDE.md` de sous-dossiers, disparaissent au `/compact`** — elles se rechargent seulement quand Claude relit un fichier concerné. Si une règle doit absolument survivre à un `/compact`, enlève son `paths:` ou déplace-la dans le `CLAUDE.md` à la racine du projet.
::

::note
**Après compaction, seuls 5 fichiers modifiés récemment sont relus automatiquement**, et un fichier de plus de 5 000 tokens revient comme simple référence de chemin plutôt qu'avec son contenu complet.
::

::warning
**Pour changer le seuil du compactage automatique**, utilise `/autocompact` avec un nombre de tokens, par exemple `/autocompact 500k`. Sans cela, Claude Code se base sur un seuil par défaut qui dépend du modèle utilisé.
::
