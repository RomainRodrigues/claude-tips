Claude Code enregistre automatiquement une photo de ton code avant chaque message que tu envoies. Ce mécanisme, les checkpoints, te permet d'annuler des changements ou de revenir en arrière en cas de dérapage.

## Quand l'utiliser

Utilise le rewind quand une modification ne donne pas le résultat attendu, quand tu veux tester une approche risquée sans t'engager, ou quand tu veux résumer une partie de la conversation pour libérer du contexte sans perdre le début de l'échange.

::note
Les checkpoints ne remplacent pas Git. Ils sont faits pour une récupération rapide au sein d'une session, pas pour un historique de version permanent.
::

## Exemple minimal

Le point d'entrée principal : appuie deux fois sur `Escape` quand le champ de saisie est vide (ou lance `/rewind`).

```text [Dans la session Claude Code]
Escape Escape
```

Le menu de rewind liste chaque message que tu as envoyé pendant la session ; choisis-en un puis une action.

## Exemple réaliste

Un refactor qui tourne mal, et comment revenir en arrière proprement.

::steps{level="3"}
### Ouvrir le menu de rewind

```text [Dans la session Claude Code]
/rewind
```

### Choisir le point de retour et l'action

Pour chaque message de la liste, quatre actions possibles (deux d'entre elles n'apparaissent que si des fichiers ont été modifiés après ce point) :

- **Restaurer le code et la conversation** : revient aux deux à la fois
- **Restaurer la conversation** : revient à ce message en gardant le code actuel
- **Restaurer le code** : annule les changements de fichiers en gardant la conversation
- **Résumer à partir d'ici** / **Résumer jusqu'ici** : compresse une partie de la conversation en un résumé, sans toucher au code sur disque

### Reprendre le travail

Après une restauration de conversation, ton prompt d'origine est remis dans le champ de saisie — tu peux le renvoyer tel quel ou le modifier avant de continuer.
::

## Pièges fréquents

::warning
**Les checkpoints ne suivent pas les fichiers modifiés par une commande Bash.** Si Claude exécute `rm fichier.txt`, `mv ancien.txt nouveau.txt` ou `cp source.txt dest.txt`, ces changements ne peuvent pas être annulés par rewind — seules les éditions faites via les outils d'édition intégrés de Claude sont suivies.
::

::caution
**Les changements faits par un subagent en arrière-plan ne sont généralement pas restaurés par rewind.** Utilise Git pour annuler ces changements-là si besoin.
::

::note
**Claude Code garde les 100 checkpoints les plus récents d'une session**, et supprime les instantanés de fichiers plus vieux qu'environ 30 jours. Un rewind vers un checkpoint dont les instantanés ont expiré peut échouer.
::

::warning
**Les fichiers liés par un lien symbolique ou un lien physique (hard link) ne sont pas restaurés.** Un `Restaurer le code` sur ces chemins affiche un avertissement et garde leur contenu actuel tel quel.
::
