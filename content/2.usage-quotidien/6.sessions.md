Une session est une conversation sauvegardée, liée à un dossier de projet. Claude Code l'enregistre en continu sur ton disque, ce qui te permet de la reprendre après avoir fermé le terminal, ou de basculer entre plusieurs tâches.

## Quand l'utiliser

Reprends une session quand une tâche s'étale sur plusieurs sessions de travail : tu évites de tout réexpliquer à Claude, qui retrouve l'historique complet de la conversation, le modèle utilisé, et (sous conditions) le mode de permission actif.

## Exemple minimal

Pour reprendre la conversation la plus récente du dossier courant :

```bash [Terminal]
claude --continue
```

Pour choisir une session dans une liste :

```bash [Terminal]
claude --resume
```

## Exemple réaliste

Un développement qui s'étale sur plusieurs jours, avec plusieurs sessions en parallèle.

::steps{level="3"}
### Reprendre la dernière session du dossier

```bash [Terminal]
claude --continue
```

Rouvre directement la conversation la plus récente démarrée dans ce dossier. S'il n'y en a pas, Claude Code te le signale et s'arrête.

### Choisir parmi plusieurs sessions

```bash [Terminal]
claude --resume
```

::code-group
```text [Depuis le picker de sessions]
↑ / ↓        naviguer entre les sessions
Entrée       reprendre la session sélectionnée
Espace       prévisualiser le contenu
Ctrl+R       renommer la session sélectionnée
Ctrl+A       afficher les sessions de tous les projets
```
::

Depuis l'intérieur d'une session déjà lancée, la même liste est accessible avec la commande slash `/resume`.

### Nommer tes sessions pour les retrouver facilement

```bash [Terminal]
claude -n auth-refactor
```

Ou pendant la session :

```text [Dans la session Claude Code]
/rename auth-refactor
```

Une session nommée se reprend directement par son nom : `claude --resume auth-refactor`.

### Reprendre une session précise par son identifiant

```bash [Terminal]
claude --resume <session-id>
```

Fonctionne même depuis un autre dossier que celui où la session a démarré : Claude Code recherche l'identifiant dans le projet courant, puis dans les autres projets de la machine.
::

## Pièges fréquents

::note
**Ce qu'une session reprise restaure** : l'historique complet de la conversation, le modèle utilisé, l'agent éventuellement utilisé, un objectif (`/goal`) encore actif, et les tâches planifiées non expirées. En revanche, des options passées au lancement comme `--mcp-config`, `--settings`, `--add-dir` ne sont **pas** restaurées automatiquement — il faut les repasser en argument si besoin.
::

::warning
**Le mode de permission n'est pas toujours restauré à l'identique.** Depuis un terminal (`claude --continue`, `claude --resume <id-ou-nom-exact>`), le mode est repris tel quel. Mais depuis le sélecteur de sessions (`claude --resume` sans argument) ou `/resume` à l'intérieur d'une session, Claude Code démarre plutôt dans le mode qu'aurait une nouvelle session — pas nécessairement celui dans lequel la session s'est terminée.
::

::caution
**Les sessions lancées avec `claude -p` (mode non-interactif) n'apparaissent pas dans le sélecteur `/resume` ni dans `claude --continue`.** Elles restent reprenables directement via `claude --resume <session-id>` en connaissant leur identifiant.
::

::note
**Les transcriptions sont stockées localement**, par défaut sous `~/.claude/projects/<projet>/<session-id>.jsonl`. Le format interne change entre les versions de Claude Code : pour exploiter les données d'une session dans un script, préfère `/export` ou les formats de sortie structurés de `claude -p` (`--output-format json`) plutôt que de lire ces fichiers directement.
::
