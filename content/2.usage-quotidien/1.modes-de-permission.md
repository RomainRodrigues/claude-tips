Le mode de permission détermine si Claude Code te demande ton accord avant de modifier un fichier, lancer une commande, ou aller sur le réseau — ou s'il agit directement.

## Quand l'utiliser

Tu n'as rien à « activer » : chaque session tourne toujours dans un mode donné, et tu peux en changer à tout moment pendant que Claude travaille. Choisis un mode plus prudent (Manuel, Plan) sur du code sensible ou un projet que tu ne connais pas encore, et un mode plus permissif (Accepter les modifs, Auto) quand tu veux avancer vite sur des tâches où tu fais confiance à Claude.

::note
Sur les plans **Pro, Max et Team**, le mode de démarrage par défaut d'une session dans le terminal est **auto** (un classifieur vérifie les actions à ta place). Sur les autres plans (Enterprise, clé API Claude Console), le mode de démarrage par défaut est **Manuel**.
::

## Exemple minimal

Le raccourci à connaître par cœur : `Shift+Tab`, pendant une session, fait défiler les modes.

```text [Dans la session Claude Code]
Manuel → Accepter les modifs → Plan → (retour à Manuel)
```

La barre de statut en bas de l'écran affiche le mode actif, par exemple `⏸ manual mode on` ou `⏵⏵ auto mode on`.

Tu peux aussi choisir le mode dès le lancement :

```bash [Terminal]
claude --permission-mode plan
```

## Exemple réaliste

Voici les modes disponibles, du plus prudent au plus permissif, avec un cas d'usage concret pour chacun.

::steps{level="3"}
### Manuel (`default`) — tout vérifier

Claude te demande confirmation avant quasiment toute action qui modifie un fichier, lance une commande shell, ou touche le réseau. Seules les lectures de fichiers passent sans demander.

```bash [Terminal]
claude --permission-mode default
```

Utile pour du code sensible, ou quand tu débutes et veux comprendre chaque action avant qu'elle se produise.

### Accepter les modifs (`acceptEdits`) — itérer vite

Claude crée et modifie des fichiers sans te demander, et peut aussi lancer sans confirmation des commandes de fichiers courantes (`mkdir`, `touch`, `mv`, `cp`, `sed`...) dans ton dossier de travail. Tu relis les changements après coup avec `git diff` plutôt qu'un par un.

### Plan — explorer avant de toucher au code

Claude lit les fichiers, explore, te propose un plan écrit — mais ne modifie rien tant que tu n'as pas validé. Idéal avant une modification qui touche plusieurs fichiers ou dont tu n'es pas sûr de l'approche.

```text [Dans la session Claude Code]
/plan ajoute l'authentification Google OAuth à l'app
```

Une fois le plan présenté, tu choisis : l'approuver (Claude passe en mode édition), ou continuer à discuter du plan.

### Auto — le mode par défaut sur Pro/Max/Team

Claude agit sans prompt pour la plupart des actions ; un second modèle (le « classifieur ») vérifie chaque action en arrière-plan et bloque ce qui sort du cadre de ta demande (déploiement en prod, suppression massive, envoi de données sensibles vers l'extérieur...).

::caution
Le mode auto réduit les interruptions mais **ne garantit pas la sécurité**. Utilise-le pour des tâches où tu fais globalement confiance à la direction prise, pas comme substitut à une relecture sur des opérations sensibles.
::
::

## Pièges fréquents

::warning
**Auto n'est pas disponible sur tous les comptes.** Il faut un modèle compatible (Opus 4.6+, Sonnet 4.6+, ou un modèle Fable sur l'API Anthropic) et un plan qui l'autorise. Si Claude Code annonce qu'auto n'est pas disponible, la session démarre en mode Manuel à la place.
::

::warning
**`bypassPermissions` (ou `--dangerously-skip-permissions`) supprime quasiment tous les prompts, y compris sur des dossiers protégés comme `.git`.** Réserve ce mode aux environnements totalement isolés (conteneur, VM jetable) où Claude Code ne peut pas causer de dégâts réels.
::

::note
**Les règles `deny` (interdiction) s'appliquent dans tous les modes, même `bypassPermissions`.** Si tu veux qu'une commande précise (par exemple `git push`) ne soit jamais exécutée sans ton accord, ajoute une règle plutôt que de compter sur le mode.
::

::caution
**`defaultMode: "auto"` dans un fichier de settings de projet ne fonctionne pas.** Ce réglage ne prend effet que dans `~/.claude/settings.json` (les settings utilisateur) — placé dans `.claude/settings.json` ou `.claude/settings.local.json` du projet, il est ignoré silencieusement.
::
