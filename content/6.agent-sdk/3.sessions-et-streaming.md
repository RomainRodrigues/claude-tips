Une **session**, dans le Agent SDK, c'est tout l'historique d'une conversation entre ton agent et Claude (prompts, appels d'outils, résultats) que le SDK écrit automatiquement sur disque pour que tu puisses y revenir plus tard.

::note
Ces mécanismes concernent le Agent SDK — le kit pour développer ton propre agent. Si tu cherches à reprendre une conversation dans le Claude Code interactif (le terminal), c'est la page [Sessions](/usage-quotidien/sessions) de la section « Utilisation quotidienne » qu'il te faut.
::

## Quand l'utiliser

Utilise la gestion de session dès que ton agent doit **répondre à plusieurs prompts qui partagent le même contexte** : un chat multi-tours, une reprise après un crash ou une limite de tours atteinte, ou une exploration de plusieurs pistes sans perdre l'historique d'origine. Pour une tâche ponctuelle en un seul appel, tu n'as besoin de rien de spécial : `query()` gère déjà tous les tours nécessaires en interne.

## Exemple minimal

Pour un chat multi-tours dans un même processus, utilise l'interface qui suit automatiquement la session pour toi : `ClaudeSDKClient` en Python, `continue: true` en TypeScript.

::code-group
```python [agent.py]
import asyncio
from claude_agent_sdk import ClaudeSDKClient, ClaudeAgentOptions

async def main():
    options = ClaudeAgentOptions(allowed_tools=["Read", "Edit", "Glob", "Grep"])

    async with ClaudeSDKClient(options=options) as client:
        # Première requête : le client capture l'ID de session en interne
        await client.query("Analyse le module d'authentification")
        async for message in client.receive_response():
            print(message)

        # Deuxième requête : continue automatiquement la même session
        await client.query("Maintenant, refactore-le pour utiliser JWT")
        async for message in client.receive_response():
            print(message)

asyncio.run(main())
```

```typescript [agent.ts]
import { query } from "@anthropic-ai/claude-agent-sdk";

// Première requête : crée une nouvelle session
for await (const message of query({
  prompt: "Analyse le module d'authentification",
  options: { allowedTools: ["Read", "Glob", "Grep"] }
})) {
  if (message.type === "result" && message.subtype === "success") {
    console.log(message.result);
  }
}

// Deuxième requête : continue: true reprend la session la plus récente
for await (const message of query({
  prompt: "Maintenant, refactore-le pour utiliser JWT",
  options: {
    continue: true,
    allowedTools: ["Read", "Edit", "Write", "Glob", "Grep"]
  }
})) {
  if (message.type === "result" && message.subtype === "success") {
    console.log(message.result);
  }
}
```
::

Dans les deux cas, le deuxième appel a accès à l'analyse faite lors du premier, sans avoir à relire les fichiers.

## Exemple réaliste

Pour reprendre une session **précise** (pas forcément la plus récente) ou explorer une alternative sans perdre l'original, capture l'ID de session puis utilise `resume` ou `fork_session` / `forkSession`.

::code-group
```python [agent.py]
import asyncio
from claude_agent_sdk import query, ClaudeAgentOptions, ResultMessage

async def main():
    # 1. Capturer l'ID de session
    session_id = None
    async for message in query(
        prompt="Analyse le module d'authentification et propose des améliorations",
        options=ClaudeAgentOptions(allowed_tools=["Read", "Glob", "Grep"]),
    ):
        if isinstance(message, ResultMessage):
            session_id = message.session_id

    # 2. Reprendre cette session précise pour agir sur l'analyse
    async for message in query(
        prompt="Implémente la refactorisation que tu as suggérée",
        options=ClaudeAgentOptions(
            resume=session_id,
            allowed_tools=["Read", "Edit", "Write", "Glob", "Grep"],
        ),
    ):
        if isinstance(message, ResultMessage) and message.subtype == "success":
            print(message.result)

    # 3. Explorer une alternative (OAuth2) sans perdre le fil JWT d'origine
    async for message in query(
        prompt="À la place de JWT, explique comment OAuth2 fonctionnerait ici",
        options=ClaudeAgentOptions(resume=session_id, fork_session=True, max_turns=5),
    ):
        if isinstance(message, ResultMessage) and message.subtype == "success":
            print(message.result)  # ceci crée une nouvelle session, l'originale reste intacte

asyncio.run(main())
```

```typescript [agent.ts]
import { query } from "@anthropic-ai/claude-agent-sdk";

// 1. Capturer l'ID de session
let sessionId: string | undefined;
for await (const message of query({
  prompt: "Analyse le module d'authentification et propose des améliorations",
  options: { allowedTools: ["Read", "Glob", "Grep"] }
})) {
  if (message.type === "result") sessionId = message.session_id;
}

// 2. Reprendre cette session précise pour agir sur l'analyse
for await (const message of query({
  prompt: "Implémente la refactorisation que tu as suggérée",
  options: { resume: sessionId, allowedTools: ["Read", "Edit", "Write", "Glob", "Grep"] }
})) {
  if (message.type === "result" && message.subtype === "success") {
    console.log(message.result);
  }
}

// 3. Explorer une alternative (OAuth2) sans perdre le fil JWT d'origine
for await (const message of query({
  prompt: "À la place de JWT, explique comment OAuth2 fonctionnerait ici",
  options: { resume: sessionId, forkSession: true, maxTurns: 5 }
})) {
  if (message.type === "result" && message.subtype === "success") {
    console.log(message.result); // ceci crée une nouvelle session, l'originale reste intacte
  }
}
```
::

::tip
**Continue vs resume vs fork** : `continue` retrouve la session la plus récente du dossier courant, sans ID à suivre. `resume` cible une session précise par son ID (utile si tu gères plusieurs utilisateurs). `fork` crée une **copie** de l'historique dans une nouvelle session — l'originale reste inchangée, ce qui te permet de tester une autre approche sans rien perdre.
::

### Streaming vs message unique

Le SDK propose deux modes d'entrée. Le **streaming** (entrée en flux continu, via un générateur asynchrone) est le mode recommandé : il permet d'envoyer des images, de mettre des messages en file d'attente, d'interrompre l'agent, et de garder une session vivante et interactive. Le **message unique** (`prompt` = une simple chaîne) est plus simple mais plus limité : pas d'images, pas de file d'attente, pas d'interruption en temps réel — adapté aux environnements sans état, comme une fonction serverless.

```typescript [agent.ts]
import { query, type SDKUserMessage } from "@anthropic-ai/claude-agent-sdk";

async function* generateMessages(): AsyncGenerator<SDKUserMessage> {
  yield {
    type: "user",
    message: { role: "user", content: "Analyse ce projet à la recherche de failles de sécurité" },
    parent_tool_use_id: null
  };
  // D'autres messages peuvent être envoyés plus tard, y compris avec des images
}

for await (const message of query({
  prompt: generateMessages(),
  options: { maxTurns: 10, allowedTools: ["Read", "Grep"] }
})) {
  if (message.type === "result" && message.subtype === "success") {
    console.log(message.result);
  }
}
```

## Pièges fréquents

::warning
**Les sessions sont locales à la machine.** Les fichiers de session vivent sous `~/.claude/projects/<dossier-encodé>/*.jsonl`. Pour reprendre une session sur une autre machine (conteneurs éphémères, CI, serverless), il faut soit passer un adaptateur `session_store` / `sessionStore`, soit déplacer le fichier `.jsonl` toi-même — `resume` seul ne suffit pas d'une machine à l'autre.
::

::caution
**Une session persiste la conversation, pas les fichiers.** Reprendre une session redonne à Claude le contexte de ce qu'il a lu et décidé, mais ne « annule » ni ne restaure aucune modification de fichier. Pour ça, il faut le [checkpointing de fichiers](https://code.claude.com/docs/en/agent-sdk/file-checkpointing), une fonctionnalité distincte.
::

::note
**`ClaudeSDKClient` (Python) n'a pas d'équivalent direct côté TypeScript.** Le SDK TypeScript n'a pas d'objet « client » qui garde la session : tu obtiens le même comportement avec `continue: true` sur des appels `query()` successifs.
::
