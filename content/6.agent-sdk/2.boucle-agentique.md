La boucle agentique est le cycle que le SDK répète tant que Claude a besoin d'appeler des outils avant de te donner une réponse finale.

::note
Cette page décrit le fonctionnement interne du **Agent SDK**, le kit pour développeurs qui construisent leur propre agent — pas une fonctionnalité que tu configures dans le terminal de Claude Code. Si tu veux juste utiliser Claude Code, tu n'as rien à faire de cette page : la boucle tourne déjà pour toi en coulisses.
::

## Quand l'utiliser

Comprendre la boucle est utile dès que tu dois **déboguer** un agent qui fait trop (ou pas assez) de tours, **limiter les coûts** avec `max_turns` / `max_budget_usd`, ou **choisir quels messages traiter** dans le flux que te renvoie `query()`. C'est la base pour tout le reste de cette section (sessions, outils personnalisés, permissions, hooks).

## Exemple minimal

Chaque itération de la boucle repose sur cinq types de messages, tous produits par le `async for` / `for await` sur `query()` :

::code-group
```python [agent.py]
import asyncio
from claude_agent_sdk import query, AssistantMessage, ResultMessage, TextBlock, ToolUseBlock

async def main():
    async for message in query(prompt="Résume ce projet"):
        if isinstance(message, AssistantMessage):
            # Chaque AssistantMessage porte un seul bloc de contenu
            for block in message.content:
                if isinstance(block, TextBlock):
                    print(f"Claude : {block.text}")
                elif isinstance(block, ToolUseBlock):
                    print(f"Appel d'outil : {block.name}")
        if isinstance(message, ResultMessage):
            if message.subtype == "success":
                print(message.result)
            else:
                print(f"Arrêté : {message.subtype}")

asyncio.run(main())
```

```typescript [agent.ts]
import { query } from "@anthropic-ai/claude-agent-sdk";

for await (const message of query({ prompt: "Résume ce projet" })) {
  if (message.type === "assistant") {
    // Chaque message assistant porte un seul bloc de contenu
    for (const block of message.message.content) {
      if (block.type === "text") {
        console.log(`Claude : ${block.text}`);
      } else if (block.type === "tool_use") {
        console.log(`Appel d'outil : ${block.name}`);
      }
    }
  }
  if (message.type === "result") {
    if (message.subtype === "success") {
      console.log(message.result);
    } else {
      console.log(`Arrêté : ${message.subtype}`);
    }
  }
}
```
::

Le déroulé, en cinq étapes :

1. **Réception du prompt** : le SDK envoie un `SystemMessage` (`subtype: "init"`) avec les métadonnées de session.
2. **Évaluation** : Claude répond avec du texte, une ou plusieurs demandes d'appel d'outil, ou les deux — un `AssistantMessage` par bloc de contenu.
3. **Exécution des outils** : le SDK exécute chaque outil demandé et renvoie les résultats à Claude.
4. **Répétition** : les étapes 2 et 3 continuent tant que Claude demande des outils. Un aller-retour complet = **un tour**.
5. **Résultat final** : quand Claude répond sans demander d'outil, le SDK envoie un dernier `AssistantMessage` textuel puis un `ResultMessage` (texte final, coût, tours utilisés, ID de session).

## Exemple réaliste

Cet exemple combine limite de tours, effort de raisonnement et gestion du résultat final pour un agent qui corrige des tests qui échouent — un cas où tu veux éviter qu'il tourne indéfiniment.

::code-group
```python [agent.py]
import asyncio
from claude_agent_sdk import query, ClaudeAgentOptions, ResultMessage

async def run_agent():
    session_id = None
    try:
        async for message in query(
            prompt="Trouve et corrige le bug qui fait échouer les tests du module auth",
            options=ClaudeAgentOptions(
                allowed_tools=["Read", "Edit", "Bash", "Glob", "Grep"],
                setting_sources=["project"],  # charge CLAUDE.md, skills, hooks du dossier courant
                max_turns=30,  # empêche une session qui tourne indéfiniment
                effort="high",  # raisonnement approfondi pour du debug complexe
            ),
        ):
            if isinstance(message, ResultMessage):
                session_id = message.session_id
                if message.subtype == "success":
                    print(f"Terminé : {message.result}")
                elif message.subtype == "error_max_turns":
                    print(f"Limite de tours atteinte. Reprends la session {session_id}.")
                elif message.subtype == "error_max_budget_usd":
                    print("Limite de budget atteinte.")
                else:
                    print(f"Arrêté : {message.subtype}")
                if message.total_cost_usd is not None:
                    print(f"Coût : ${message.total_cost_usd:.4f}")
    except Exception as error:
        # Un appel query() à un seul tour lève une exception après avoir renvoyé
        # un résultat d'erreur — d'où le bloc try.
        print(f"Session terminée avec une erreur : {error}")

asyncio.run(run_agent())
```

```typescript [agent.ts]
import { query } from "@anthropic-ai/claude-agent-sdk";

let sessionId: string | undefined;

try {
  for await (const message of query({
    prompt: "Trouve et corrige le bug qui fait échouer les tests du module auth",
    options: {
      allowedTools: ["Read", "Edit", "Bash", "Glob", "Grep"],
      settingSources: ["project"], // charge CLAUDE.md, skills, hooks du dossier courant
      maxTurns: 30, // empêche une session qui tourne indéfiniment
      effort: "high" // raisonnement approfondi pour du debug complexe
    }
  })) {
    if (message.type === "system" && message.subtype === "init") {
      sessionId = message.session_id;
    }
    if (message.type === "result") {
      if (message.subtype === "success") {
        console.log(`Terminé : ${message.result}`);
      } else if (message.subtype === "error_max_turns") {
        console.log(`Limite de tours atteinte. Reprends la session ${sessionId}.`);
      } else if (message.subtype === "error_max_budget_usd") {
        console.log("Limite de budget atteinte.");
      } else {
        console.log(`Arrêté : ${message.subtype}`);
      }
      console.log(`Coût : $${message.total_cost_usd.toFixed(4)}`);
    }
  }
} catch (error) {
  console.log(`Session terminée avec une erreur : ${error}`);
}
```
::

`max_turns` compte uniquement les tours avec appel d'outil ; `max_budget_usd` plafonne la dépense totale (y compris celle des subagents). Quand une limite est atteinte, le `ResultMessage` a un `subtype` du genre `error_max_turns` ou `error_max_budget_usd` — tu peux alors reprendre la session avec une limite plus haute (voir la page [Sessions et streaming](/agent-sdk/sessions-et-streaming)).

## Pièges fréquents

::warning
**Ne pas mettre de limite sur un prompt ouvert.** Sans `max_turns` ni `max_budget_usd`, la boucle tourne jusqu'à ce que Claude termine de lui-même. Pour une tâche bien délimitée ("corrige ce bug précis"), c'est très bien. Pour un prompt vague ("améliore ce code"), ça peut tourner longtemps et coûter cher. Mets toujours une limite en production.
::

::caution
**`query()` lève une exception après un résultat d'erreur.** Un appel `query()` à un seul tour (pas de session persistante) relance une erreur juste après avoir émis le `ResultMessage` d'échec (`error_max_turns`, par exemple). Si ton code doit continuer après ça, entoure la boucle d'un `try`/`except` (Python) ou `try`/`catch` (TypeScript).
::

::note
**Le champ `result` n'existe que sur un succès.** Il n'est présent que quand `subtype == "success"` — vérifie toujours le `subtype` avant de lire `result`, sinon tu lis une valeur absente sur les autres types de fin (`error_max_turns`, `error_during_execution`, etc.).
::
