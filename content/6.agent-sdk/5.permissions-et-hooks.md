Les **permissions** décident quels outils s'exécutent automatiquement et lesquels ont besoin d'une validation ; les **hooks** sont des callbacks qui s'exécutent à des moments précis de la boucle agentique (avant un outil, après, à l'arrêt de l'agent...) pour observer ou modifier son comportement.

::note
Ces réglages s'appliquent au **Agent SDK** — le kit pour développer ton propre agent. Les modes de permission du Claude Code interactif (normal / plan / auto-accept, `Shift+Tab`) sont couverts dans [Modes de permission](/usage-quotidien/modes-de-permission), une page différente pour un outil différent.
::

## Quand l'utiliser

Configure des **règles de permission** dès que tu veux qu'un agent tourne sans supervision humaine à chaque étape, tout en gardant un contrôle explicite sur ce qui est permis (par exemple : lecture libre, mais écriture interdite hors d'un dossier précis). Utilise des **hooks** quand une règle statique ne suffit pas : tu as besoin de logique custom (bloquer selon le contenu d'un fichier, logger chaque appel, injecter du contexte, demander une validation humaine sur une action sensible).

## Exemple minimal

Pour un agent en lecture seule qui ne demande jamais confirmation, combine `allowedTools` avec le mode `dontAsk` : tout ce qui n'est pas explicitement listé est refusé au lieu de déclencher une invite.

::code-group
```python [agent.py]
import asyncio
from claude_agent_sdk import query, ClaudeAgentOptions, ResultMessage

async def main():
    options = ClaudeAgentOptions(
        allowed_tools=["Read", "Glob", "Grep"],
        permission_mode="dontAsk",
    )
    async for message in query(prompt="Explique l'architecture de ce projet", options=options):
        if isinstance(message, ResultMessage) and message.subtype == "success":
            print(message.result)

asyncio.run(main())
```

```typescript [agent.ts]
import { query } from "@anthropic-ai/claude-agent-sdk";

for await (const message of query({
  prompt: "Explique l'architecture de ce projet",
  options: {
    allowedTools: ["Read", "Glob", "Grep"],
    permissionMode: "dontAsk"
  }
})) {
  if (message.type === "result" && message.subtype === "success") {
    console.log(message.result);
  }
}
```
::

::field-group
  :::field{name="default" type="mode"}
  Comportement standard : les appels qui ont besoin d'une validation et qu'aucune règle n'autorise déclenchent ton callback `canUseTool` ; sans callback, c'est refusé.
  :::
  :::field{name="acceptEdits" type="mode"}
  Auto-approuve les modifications de fichiers et les commandes filesystem courantes (`mkdir`, `mv`, `cp`...). Le reste suit les règles normales.
  :::
  :::field{name="plan" type="mode"}
  Claude explore et planifie sans jamais modifier tes fichiers sources ; toute édition passe par ton callback.
  :::
  :::field{name="dontAsk" type="mode"}
  Ne demande jamais : tout ce qui aurait déclenché une invite est refusé à la place.
  :::
  :::field{name="bypassPermissions" type="mode"}
  Approuve tout, sauf quelques exceptions de sécurité fixes. À réserver à des environnements isolés (CI, conteneurs).
  :::
::

## Exemple réaliste

Cet exemple combine une règle déclarative (`allowedTools`) avec un **hook `PreToolUse`** qui bloque toute tentative d'écriture ou de modification d'un fichier `.env`, quelle que soit la règle de permission active — les hooks s'exécutent avant tout le reste de l'évaluation.

::code-group
```python [agent.py]
import asyncio
from claude_agent_sdk import (
    AssistantMessage,
    ClaudeSDKClient,
    ClaudeAgentOptions,
    HookMatcher,
    ResultMessage,
)

# Le callback reçoit les détails de l'appel d'outil
async def protect_env_files(input_data, tool_use_id, context):
    file_path = input_data["tool_input"].get("file_path", "")
    file_name = file_path.split("/")[-1]

    if file_name == ".env":
        return {
            "hookSpecificOutput": {
                "hookEventName": input_data["hook_event_name"],
                "permissionDecision": "deny",
                "permissionDecisionReason": "Impossible de modifier les fichiers .env",
            }
        }
    return {}  # objet vide = on laisse passer

async def main():
    options = ClaudeAgentOptions(
        hooks={
            # Enregistré pour PreToolUse, filtré sur les outils d'écriture
            "PreToolUse": [HookMatcher(matcher="Write|Edit", hooks=[protect_env_files])]
        }
    )

    async with ClaudeSDKClient(options=options) as client:
        await client.query("Crée un fichier .env avec une config de base de données locale")
        async for message in client.receive_response():
            if isinstance(message, (AssistantMessage, ResultMessage)):
                print(message)

asyncio.run(main())
```

```typescript [agent.ts]
import { query, HookCallback, PreToolUseHookInput } from "@anthropic-ai/claude-agent-sdk";

// Le callback reçoit les détails de l'appel d'outil
const protectEnvFiles: HookCallback = async (input, toolUseID, { signal }) => {
  const preInput = input as PreToolUseHookInput;
  const toolInput = preInput.tool_input as Record<string, unknown>;
  const filePath = toolInput?.file_path as string;
  const fileName = filePath?.split("/").pop();

  if (fileName === ".env") {
    return {
      hookSpecificOutput: {
        hookEventName: preInput.hook_event_name,
        permissionDecision: "deny",
        permissionDecisionReason: "Impossible de modifier les fichiers .env"
      }
    };
  }
  return {}; // objet vide = on laisse passer
};

for await (const message of query({
  prompt: "Crée un fichier .env avec une config de base de données locale",
  options: {
    hooks: {
      // Enregistré pour PreToolUse, filtré sur les outils d'écriture
      PreToolUse: [{ matcher: "Write|Edit", hooks: [protectEnvFiles] }]
    }
  }
})) {
  if (message.type === "assistant" || message.type === "result") {
    console.log(message);
  }
}
```
::

Quand tu lances ce script, Claude tente de créer le fichier `.env`, le hook bloque l'opération, et Claude explique dans sa réponse finale qu'il n'a pas pu le faire.

## Pièges fréquents

::warning
**Un outil auto-approuvé ne passe jamais par ton callback `canUseTool`.** Un appel validé plus tôt dans la chaîne d'évaluation — par une règle `allowedTools`, par `acceptEdits`, ou par `bypassPermissions` — ne déclenche jamais ton `canUseTool`, même si tu en as défini un. Pour un contrôle qui s'applique à **tous** les appels sans exception, utilise plutôt un hook `PreToolUse` : les hooks s'exécutent avant toute règle de permission.
::

::caution
**`allowedTools` ne restreint pas `bypassPermissions`.** Lister seulement `["Read"]` dans `allowedTools` tout en étant en mode `bypassPermissions` approuve quand même **tous** les outils, y compris `Bash` ou `Write` — les outils non listés ne sont simplement pas couverts par une règle et retombent alors sur le mode de permission actif, qui approuve tout. Pour bloquer des outils précis en `bypassPermissions`, utilise `disallowedTools`.
::

::note
**`SessionStart` et `SessionEnd` n'existent pas en callback côté Python.** Ces deux hooks ne sont disponibles qu'en TypeScript comme callbacks SDK ; en Python, ils ne fonctionnent que comme hooks « commande shell » définis dans `.claude/settings.json`, chargés via `setting_sources=["project"]`.
::

::warning
**Plusieurs hooks sur le même événement s'exécutent en parallèle.** Si un hook renvoie `deny` et un autre `allow` pour le même appel, `deny` l'emporte toujours — écris chaque hook comme s'il agissait seul, sans dépendre de l'ordre d'exécution d'un autre.
::
