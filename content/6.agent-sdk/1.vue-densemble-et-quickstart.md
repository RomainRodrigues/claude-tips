Le **Agent SDK** est une bibliothèque (Python ou TypeScript) qui te donne accès aux mêmes outils, à la même boucle agentique et à la même gestion du contexte que Claude Code, mais programmables dans ton propre code.

::note
**Ce n'est pas Claude Code.** Claude Code est l'outil en ligne de commande que tu utilises dans ton terminal pour coder avec l'aide de Claude. Le Agent SDK, lui, sert à **construire ton propre outil ou agent IA** qui réutilise ce même moteur — par exemple un assistant qui corrige automatiquement des bugs, un bot de support, ou un agent intégré dans ton produit. Si tu veux juste utiliser Claude Code au quotidien, cette section ne te concerne pas : reviens aux sections précédentes du site.
::

## Quand l'utiliser

Utilise le Agent SDK si tu es développeur·euse et que tu veux **coder une application qui pilote un agent Claude**, sans réimplémenter toi-même la boucle qui appelle les outils, lit les résultats et décide de la suite. Si tu veux seulement lancer des commandes Claude Code depuis un script shell ou une CI, la commande `claude -p` (mode headless) suffit généralement — voir [le mode headless](/automatiser/mode-headless-et-scripts). Le SDK est fait pour des cas plus poussés : outils personnalisés, plusieurs agents orchestrés, intégration dans un produit existant.

## Exemple minimal

Installe le SDK dans un nouveau dossier de projet, puis fixe ta clé d'API :

::code-group
```bash [TypeScript]
mkdir mon-agent && cd mon-agent
npm init -y
npm pkg set type=module
npm install @anthropic-ai/claude-agent-sdk
npm install --save-dev tsx
```

```bash [Python (uv)]
mkdir mon-agent && cd mon-agent
uv init
uv add claude-agent-sdk
```
::

```bash [Terminal]
export ANTHROPIC_API_KEY=ta-clé-api
```

::note
Le SDK va chercher la clé dans les variables d'environnement du processus qui lance ton agent — il ne lit **pas** automatiquement un fichier `.env`. Récupère une clé sur la [Claude Console](https://platform.claude.com/).
::

Puis écris ton premier agent, qui répond simplement à une question :

::code-group
```typescript [agent.ts]
import { query } from "@anthropic-ai/claude-agent-sdk";

for await (const message of query({
  prompt: "Combien de fichiers y a-t-il dans ce dossier ?",
  options: { allowedTools: ["Glob"] }
})) {
  if (message.type === "result" && message.subtype === "success") {
    console.log(message.result);
  }
}
```

```python [agent.py]
import asyncio
from claude_agent_sdk import query, ClaudeAgentOptions, ResultMessage

async def main():
    async for message in query(
        prompt="Combien de fichiers y a-t-il dans ce dossier ?",
        options=ClaudeAgentOptions(allowed_tools=["Glob"]),
    ):
        if isinstance(message, ResultMessage) and message.subtype == "success":
            print(message.result)

asyncio.run(main())
```
::

```bash [Terminal]
npx tsx agent.ts
# ou : uv run agent.py
```

`query()` est le point d'entrée : tu lui donnes un `prompt` (ce que tu veux que Claude fasse) et des `options` (quels outils autoriser, quel mode de permission, etc.), et elle te renvoie un flux de messages au fur et à mesure que Claude travaille.

## Exemple réaliste

Voici l'exemple du quickstart officiel : un agent qui lit un fichier Python, repère des bugs, et les corrige tout seul.

::steps{level="3"}
### Créer un fichier avec des bugs

```python [utils.py]
def calculate_average(numbers):
    total = 0
    for num in numbers:
        total += num
    return total / len(numbers)


def get_user_name(user):
    return user["name"].upper()
```

Ce code plante si `numbers` est une liste vide (division par zéro) ou si `user` vaut `None`.

### Écrire l'agent

::code-group
```python [agent.py]
import asyncio
from claude_agent_sdk import query, ClaudeAgentOptions, AssistantMessage, ResultMessage

async def main():
    # Boucle agentique : les messages arrivent au fur et à mesure
    async for message in query(
        prompt="Vérifie utils.py à la recherche de bugs qui provoqueraient des plantages. Corrige-les.",
        options=ClaudeAgentOptions(
            allowed_tools=["Read", "Edit", "Glob"],  # outils auto-approuvés
            permission_mode="acceptEdits",  # auto-approuve les modifications de fichiers
        ),
    ):
        if isinstance(message, AssistantMessage):
            for block in message.content:
                if hasattr(block, "text"):
                    print(block.text)  # le raisonnement de Claude
                elif hasattr(block, "name"):
                    print(f"Outil : {block.name}")  # l'outil appelé
        elif isinstance(message, ResultMessage):
            print(f"Terminé : {message.subtype}")

asyncio.run(main())
```

```typescript [agent.ts]
import { query } from "@anthropic-ai/claude-agent-sdk";

for await (const message of query({
  prompt: "Vérifie utils.py à la recherche de bugs qui provoqueraient des plantages. Corrige-les.",
  options: {
    allowedTools: ["Read", "Edit", "Glob"], // outils auto-approuvés
    permissionMode: "acceptEdits" // auto-approuve les modifications de fichiers
  }
})) {
  if (message.type === "assistant" && message.message?.content) {
    for (const block of message.message.content) {
      if ("text" in block) {
        console.log(block.text); // le raisonnement de Claude
      } else if ("name" in block) {
        console.log(`Outil : ${block.name}`); // l'outil appelé
      }
    }
  } else if (message.type === "result") {
    console.log(`Terminé : ${message.subtype}`);
  }
}
```
::

### Lancer l'agent

```bash [Terminal]
uv run agent.py
# ou : npx tsx agent.ts
```

L'agent affiche son raisonnement et chaque outil qu'il appelle, puis termine par `Terminé : success`. En ouvrant `utils.py`, tu verras du code défensif ajouté pour gérer la liste vide et l'utilisateur `None`.
::

Trois éléments à retenir dans cet exemple :

- **`query`** : le point d'entrée qui crée la boucle agentique. C'est un itérateur asynchrone, donc tu boucles dessus (`async for` / `for await`).
- **`prompt`** : ce que tu veux que Claude fasse, en langage naturel. Claude choisit lui-même les outils à utiliser.
- **`options`** : la configuration — ici `allowedTools` pour pré-approuver `Read`, `Edit` et `Glob`, et `permissionMode: "acceptEdits"` pour auto-approuver les modifications de fichiers.

## Pièges fréquents

::warning
**Confondre Agent SDK et Claude Code.** Si ton besoin est « je veux utiliser Claude dans mon terminal pour coder », tu n'as pas besoin du SDK : installe directement Claude Code (voir [Installation et premier lancement](/demarrer/installation-premier-lancement)). Le SDK sert à construire un **nouveau** produit ou agent, pas à utiliser celui qui existe déjà.
::

::caution
**Oublier `ANTHROPIC_API_KEY`.** Sans cette variable d'environnement définie dans le shell qui lance ton script, tu obtiens une erreur `Not logged in` ou `Invalid API key`. Le SDK ne charge pas de fichier `.env` tout seul — utilise un paquet comme `dotenv` si tu veux garder ta clé dans un fichier.
::

::note
**Anthropic n'autorise pas la connexion claude.ai dans un produit tiers.** Sauf autorisation explicite préalable, les agents construits avec le SDK doivent s'authentifier par clé d'API (ou via Bedrock/Vertex/Foundry), pas en réutilisant la connexion claude.ai d'un utilisateur.
::
