Les règles de permission décident, outil par outil et commande par commande, ce que Claude Code peut faire sans confirmation, ce qui déclenche une question, et ce qui est totalement interdit.

## Quand l'utiliser

Utilise des règles de permission dès que le mode par défaut (qui demande confirmation à chaque nouvel outil) devient trop lent pour ton usage quotidien, ou au contraire dès que tu veux verrouiller certaines actions (empêcher la lecture d'un `.env`, interdire `git push`) quel que soit le mode de permission actif.

::note
Ces règles sont appliquées par Claude Code lui-même, pas par le modèle. Une instruction dans ton prompt ou ton `CLAUDE.md` peut orienter ce que Claude *essaie* de faire, mais ne change jamais ce que Claude Code *autorise*.
::

## Exemple minimal

Une règle de permission suit la forme `Outil` ou `Outil(spécificateur)`. Ce fichier autorise les commits git et les scripts npm sans demander, et bloque tous les `git push` :

```json [~/.claude/settings.json]
{
  "permissions": {
    "allow": [
      "Bash(npm run *)",
      "Bash(git commit *)"
    ],
    "deny": [
      "Bash(git push *)"
    ]
  }
}
```

Tu peux aussi gérer ces règles depuis une session, sans éditer de fichier :

```text [Dans une session Claude Code]
/permissions
```

## Exemple réaliste

Un fichier de projet plus complet, qui combine plusieurs types de règles : commandes shell, lecture de fichiers, et accès web.

```json [.claude/settings.json] {3-6,8-11,13}
{
  "permissions": {
    "allow": [
      "Bash(npm run *)",
      "Bash(git commit *)",
      "WebFetch(domain:docs.anthropic.com)"
    ],
    "ask": [
      "Bash(git push *)",
      "Bash(npm publish *)"
    ],
    "deny": [
      "Read(./.env)",
      "Read(./.env.*)",
      "Read(./secrets/**)"
    ]
  }
}
```

Avec cette configuration :
- Claude lance les scripts npm et fait des commits sans jamais te demander.
- Il te demande confirmation avant un `git push` ou une publication npm.
- Il ne peut ni lire ni écrire dans `.env` ou `secrets/`, quel que soit l'outil utilisé (Edit, Write, ou une commande comme `cat` en Bash).

## Comment les règles se combinent

Les règles sont évaluées dans un ordre fixe : **deny, puis ask, puis allow**. La première qui correspond l'emporte — peu importe qu'une autre règle soit plus précise.

::warning
**Une règle `deny` large bloque tout, même une règle `allow` plus spécifique.** `Bash(aws *)` en deny bloque `Bash(aws s3 ls)` même si ce dernier est aussi dans `allow`. Une règle `allow` ne peut jamais créer d'exception dans une règle `deny`.
::

## Pièges fréquents

::warning
**Place le `*` après la sous-commande, pas avant.** Dans `git log --oneline main`, `git` est le programme et `log` la sous-commande. Claude Code ne considère comme fixe que ce qui précède le premier `*` : `Bash(git log *)` n'autorise que `git log`, alors que `Bash(git *)` autorise **toutes** les commandes git. Claude Code affiche un avertissement au démarrage si une règle `allow` place un `*` avant la sous-commande.
::

::caution
**Une règle Bash ne bloque que le texte exact de la commande, pas le programme lui-même.** `Bash(curl *)` en deny arrête `curl https://...` mais pas `/usr/bin/curl https://...` ni `sh -c 'curl https://...'`. Ce n'est pas une barrière de sécurité au niveau du système — pour ça, il faut le [sandboxing](https://code.claude.com/docs/en/sandboxing) ou un hook `PreToolUse` qui inspecte la commande avant exécution.
::

::note
**`Read` et `Edit` sont les deux seuls types de règles pour les fichiers.** Une règle écrite pour `Write`, `NotebookEdit` ou `Glob` est acceptée mais jamais consultée : utilise `Edit(chemin/**)` à la place de `Write(chemin/**)`, et `Read(chemin/**)` à la place de `Glob(chemin/**)`. Claude Code avertit au démarrage si une règle est mal ciblée.
::

::caution
**`WebFetch` seul n'empêche pas Claude d'accéder au réseau.** Si Bash reste autorisé, Claude peut toujours utiliser `curl` ou `wget` pour atteindre n'importe quelle URL. Pour restreindre vraiment l'accès réseau, combine une règle `deny` sur les commandes réseau en Bash avec des règles `WebFetch(domain:...)` précises, ou utilise le sandboxing.
::
