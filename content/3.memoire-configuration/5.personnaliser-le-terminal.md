Claude Code fonctionne sans configuration dans n'importe quel terminal, mais tu peux personnaliser trois choses : une **statusline** (barre d'info en bas de l'écran), le **rendu plein écran** (moins de scintillement, souris utilisable), et le confort d'usage avec un **lecteur d'écran** ou d'autres besoins d'accessibilité.

## Quand l'utiliser

Ajoute une statusline dès que tu veux garder un œil en permanence sur le modèle actif, l'usage du contexte, ou le coût de la session. Active le rendu plein écran si l'affichage scintille ou si le défilement saute pendant que Claude travaille — c'est fréquent dans le terminal intégré de VS Code, tmux, ou iTerm2. Active le mode lecteur d'écran si tu utilises VoiceOver, NVDA ou un outil équivalent.

## Exemple minimal

Le plus simple pour une statusline : décrire ce que tu veux en langage naturel, et laisser Claude Code générer le script.

```text [Dans une session Claude Code]
/statusline affiche le nom du modèle et le pourcentage de contexte utilisé
```

Claude Code écrit un script dans `~/.claude/` et met à jour tes settings automatiquement. Pour basculer en plein écran :

```text [Dans une session Claude Code]
/tui fullscreen
```

## Exemple réaliste

Une statusline manuelle, écrite à la main, qui affiche le modèle, le dossier courant et le pourcentage de contexte utilisé.

::steps{level="3"}
### Écrire le script

```bash [~/.claude/statusline.sh]
#!/bin/bash
# Claude Code envoie le JSON de la session sur stdin
input=$(cat)

MODEL=$(echo "$input" | jq -r '.model.display_name')
DIR=$(echo "$input" | jq -r '.workspace.current_dir')
PCT=$(echo "$input" | jq -r '.context_window.used_percentage // 0' | cut -d. -f1)

echo "[$MODEL] 📁 ${DIR##*/} | ${PCT}% contexte"
```

### Le rendre exécutable

```bash [Terminal]
chmod +x ~/.claude/statusline.sh
```

### Le déclarer dans les settings

```json [~/.claude/settings.json]
{
  "statusLine": {
    "type": "command",
    "command": "~/.claude/statusline.sh",
    "padding": 2
  }
}
```

Claude Code recharge les settings automatiquement et exécute le script dès que tu enregistres.
::

Le script reçoit un objet JSON complet sur son entrée standard, avec des champs comme `model.display_name`, `cost.total_cost_usd`, `context_window.used_percentage`, ou `workspace.current_dir` — largement de quoi construire une barre de statut riche (coût, branche git, durée de session...).

## Adapter le terminal à tes besoins

::tabs
  :::tabs-item{label="Lecteur d'écran" icon="i-lucide-ear"}
  Le mode lecteur d'écran remplace l'interface visuelle par du texte simple, ligne par ligne, sans redessin ni animation. Active-le pour une session avec `claude --ax-screen-reader`, pour un shell avec la variable `CLAUDE_AX_SCREEN_READER=1`, ou en permanence avec `"axScreenReader": true` dans tes settings utilisateur.
  :::

  :::tabs-item{label="Réduire les animations" icon="i-lucide-zap-off"}
  Sans passer par le mode lecteur d'écran complet, tu peux couper les animations (spinners, effets de scintillement) avec `"prefersReducedMotion": true` dans tes settings.
  :::

  :::tabs-item{label="Thème adapté au daltonisme" icon="i-lucide-palette"}
  Utilise la commande `/theme` pour choisir un thème, dont les variantes `dark-daltonized` et `light-daltonized` conçues pour le daltonisme.
  :::
::

## Pièges fréquents

::warning
**Shift+Enter ne fonctionne pas pour insérer un retour à la ligne dans certains terminaux.** Dans VS Code, Cursor, ou Zed, il faut lancer `/terminal-setup` une fois pour l'activer. Dans gnome-terminal ou les IDE JetBrains, ce n'est pas disponible du tout : utilise `Ctrl+J`, ou tape `\` puis Entrée, qui fonctionnent partout sans configuration.
::

::note
**Le rendu plein écran est en research preview.** Son comportement peut encore changer. Pour revenir à l'ancien rendu, lance `/tui default`. En mode lecteur d'écran, Claude Code utilise toujours le rendu classique et ignore le plein écran, sauf dans les sessions en arrière-plan attachées.
::

::caution
**Une statusline personnalisée fait disparaître certains raccourcis affichés en bas de l'écran**, comme `esc to interrupt`. C'est normal : la statusline s'affiche dans sa propre ligne au-dessus de ces indications, et Claude Code réduit l'espace occupé par les indications par défaut pour compenser.
::

::note
**Le mode lecteur d'écran ne s'active jamais tout seul.** Même si un lecteur d'écran tourne sur ta machine, Claude Code ne le détecte pas automatiquement — il faut l'activer explicitement via le flag, la variable d'environnement, ou le réglage `axScreenReader`.
::
