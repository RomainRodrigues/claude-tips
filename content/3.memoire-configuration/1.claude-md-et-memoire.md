Chaque session de Claude Code démarre avec une mémoire vierge. Le fichier `CLAUDE.md` (des instructions que **tu** écris) et la mémoire automatique (des notes que **Claude** écrit lui-même) sont les deux mécanismes qui font passer des informations d'une session à la suivante.

## Quand l'utiliser

Utilise `CLAUDE.md` dès que tu te surprends à répéter la même consigne à chaque nouvelle session : la commande pour lancer les tests, une convention de nommage, une règle métier. La mémoire automatique, elle, ne demande rien : elle se déclenche seule quand tu corriges Claude ou que tu lui donnes une préférence («utilise pnpm, pas npm»).

::note
Les deux sont chargés au début de chaque conversation, mais restent de simples instructions : Claude essaie de les suivre, sans garantie absolue. Pour bloquer une action de façon certaine (empêcher un `git push`, par exemple), il faut un hook, pas une ligne de CLAUDE.md.
::

## Exemple minimal

Le plus rapide pour démarrer : laisser Claude générer le fichier à partir de ton code.

```text [Dans une session Claude Code]
/init
```

Claude analyse le projet et écrit un `CLAUDE.md` à la racine avec les commandes de build, de test, et les conventions qu'il a repérées. S'il en existe déjà un, `/init` propose des améliorations plutôt que de l'écraser.

Un `CLAUDE.md` minimal ressemble à ceci :

```markdown [CLAUDE.md]
# Mon projet

## Commandes
- `pnpm dev` : serveur de développement
- `pnpm test` : lance les tests

## Conventions
- Indentation en 2 espaces
- Les composants React vivent dans `src/components/`
```

## Exemple réaliste

Sur un vrai projet, tu combines plusieurs éléments : le fichier principal, un import vers un autre document, et une préférence personnelle non partagée avec l'équipe.

::steps{level="3"}
### Écrire le CLAUDE.md du projet

Crée `./CLAUDE.md` (ou `./.claude/CLAUDE.md`) à la racine, et commite-le : c'est partagé avec toute l'équipe via Git.

```markdown [CLAUDE.md] {5}
# claude-tips

Documentation Nuxt Content sur Claude Code.

Voir @docs/architecture.md pour le détail des collections Nuxt Content.

## Commandes
- `pnpm lint` : zéro erreur exigé avant commit
- `pnpm build` : à lancer avant de considérer une étape terminée
```

La ligne `@docs/architecture.md` importe le contenu de ce fichier directement dans le contexte, comme si tu l'avais collé ici.

### Ajouter tes préférences personnelles

Crée un `CLAUDE.local.md` à la racine pour tes réglages perso, non partagés :

```markdown [CLAUDE.local.md]
# Préférences perso
- Mon serveur de test local tourne sur le port 4000
- Je préfère que les commits restent en anglais
```

Ajoute-le à ton `.gitignore` (Claude Code ne le fait pas automatiquement, contrairement à `settings.local.json`).

### Vérifier que tout est bien chargé

```text [Dans une session Claude Code]
/context
```

La section **Memory files** liste chaque fichier CLAUDE.md et CLAUDE.local.md effectivement chargé pour cette session.

### Laisser la mémoire automatique travailler

Pendant que tu travailles, dis simplement à Claude ce qu'il doit retenir :

```text [Dans une session Claude Code]
retiens qu'on utilise toujours pnpm, jamais npm, sur ce projet
```

Claude enregistre la note dans `~/.claude/projects/<projet>/memory/`, sous forme de fichiers markdown que tu peux relire avec `/memory`.
::

## Pièges fréquents

::warning
**Un CLAUDE.md trop long réduit son efficacité.** Vise moins de 200 lignes par fichier : au-delà, Claude Code consomme plus de contexte et suit les instructions moins fidèlement. Si le fichier grossit trop, découpe-le avec des [règles ciblées](https://code.claude.com/docs/en/memory#organize-rules-with-claude/rules/) dans `.claude/rules/`, qui ne se chargent que pour les fichiers concernés.
::

::caution
**CLAUDE.md n'est pas une barrière de sécurité.** Le contenu est livré comme un message après le prompt système, pas comme une règle contraignante : Claude essaie de suivre les instructions, mais rien ne l'empêche de s'en écarter sur une consigne vague ou contradictoire. Pour bloquer une action à coup sûr (empêcher la lecture d'un fichier `.env`, par exemple), utilise plutôt un hook `PreToolUse` ou une règle de permission.
::

::note
**`CLAUDE.local.md` n'est pas mis au `.gitignore` automatiquement**, contrairement à `.claude/settings.local.json`. Ajoute-le toi-même à ton `.gitignore` pour éviter de le committer par erreur.
::

::note
**Si deux fichiers CLAUDE.md se contredisent, Claude choisit arbitrairement.** Relis périodiquement tes fichiers CLAUDE.md (racine, sous-dossiers, `.claude/rules/`) pour supprimer les instructions obsolètes ou en conflit.
::
