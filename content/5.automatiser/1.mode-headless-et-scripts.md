Le mode headless (« sans tête ») lance Claude Code une seule fois avec une instruction, imprime le résultat, puis quitte — sans ouvrir de session interactive. C'est ce qui permet d'utiliser Claude Code comme n'importe quel autre outil en ligne de commande dans un script ou un pipe.

## Quand l'utiliser

Dès que tu veux que Claude fasse une tâche précise sans que personne ne reste devant le terminal pour répondre à des questions : un script de build, une commande dans un `package.json`, un pipe Unix, ou une étape de pipeline CI/CD (voir la page suivante sur GitHub Actions et GitLab CI). En session interactive normale, tu discutes avec Claude ; en mode headless, tu l'appelles comme une fonction qui prend du texte en entrée et renvoie du texte en sortie.

## Exemple minimal

Ajoute le flag `-p` (ou `--print`) à `claude` pour passer en mode non interactif :

```bash [Terminal]
claude -p "que fait le module d'authentification ?"
```

Claude Code lit le dossier courant, répond une seule fois dans le terminal, puis quitte. Le code de sortie est `0` en cas de succès et différent de `0` en cas d'échec — pratique pour faire une condition dans un script.

Tu peux aussi lui envoyer du texte via un pipe, comme avec n'importe quelle commande Unix :

```bash [Terminal]
cat build-error.txt | claude -p "explique en une phrase la cause de cette erreur de build" > output.txt
```

::note
Le flux passé sur l'entrée standard (stdin) est limité à 10 Mo. Au-delà, Claude Code s'arrête avec une erreur claire plutôt que de tronquer silencieusement — écris le contenu dans un fichier et référence son chemin dans le prompt à la place.
::

## Exemple réaliste

Un cas courant : brancher Claude Code comme relecteur de typos dans un script `package.json`, appelé sur le diff par rapport à `main`.

```json [package.json]
{
  "scripts": {
    "lint:claude": "git diff main | claude -p \"tu es un correcteur de fautes de frappe. pour chaque faute dans ce diff, indique fichier:ligne sur une ligne puis le problème sur la ligne suivante. ne renvoie rien d'autre.\""
  }
}
```

On lance ensuite `npm run lint:claude`. Passer le diff par un pipe évite à Claude d'avoir besoin de la permission Bash pour aller le lire lui-même.

Pour un usage scripté ou en CI, ajoute `--bare` : Claude Code démarre plus vite en sautant la découverte automatique des hooks, skills, commandes personnalisées, subagents, plugins, serveurs MCP, mémoire auto et `CLAUDE.md`. Résultat identique sur toutes les machines, sans dépendre de la configuration locale de qui lance le script :

```bash [Terminal]
claude --bare -p "résume le fichier README.md" --allowedTools "Read"
```

Pour obtenir une sortie exploitable par un autre programme plutôt que du texte libre, utilise `--output-format json` : la réponse inclut alors le texte dans le champ `result`, l'identifiant de session, et le coût de l'appel. Combine-la avec [`jq`](https://jqlang.org/) pour extraire ce qui t'intéresse :

```bash [Terminal]
claude -p "résume ce projet" --output-format json | jq -r '.result'
```

Pour enchaîner plusieurs appels sur la même conversation, utilise `--continue` :

```bash [Terminal]
claude -p "relis ce projet et repère les problèmes de performance"
claude -p "concentre-toi maintenant sur les requêtes en base de données" --continue
claude -p "fais un résumé de tous les problèmes trouvés" --continue
```

## Pièges fréquents

::warning
**Le mode par défaut de `-p` bloque tout ce qui demanderait confirmation.** Contrairement à une session interactive, `claude -p` démarre toujours en mode de permission Manuel, quel que soit ton plan d'abonnement. Sans confirmation possible (personne devant l'écran), toute action qui aurait normalement affiché une invite est refusée. Utilise `--allowedTools` pour autoriser des outils précis, ou `--permission-mode` (par exemple `acceptEdits` ou `auto`) pour changer le mode de base de la session. Pour un run totalement sans surveillance (comme une tâche planifiée), ajoute aussi `--permission-prompts none`.
::

::caution
**Sans `--bare`, `-p` charge la configuration du dossier courant — y compris dans un dossier auquel tu ne fais pas confiance.** Un hook dans le `.claude/settings.json` du projet ou un serveur MCP dans son `.mcp.json` s'exécute automatiquement, sans la moindre boîte de dialogue de confiance ni demande d'approbation par serveur, contrairement à une session interactive. En script ou en CI, préfère `--bare` pour ne charger que ce que tu passes explicitement (`--append-system-prompt`, `--settings`, `--mcp-config`, `--agents`, `--plugin-dir`/`--plugin-url`).
::

::note
**`--bare` n'utilise pas ta connexion par abonnement.** En mode `--bare`, Claude Code ne lit jamais tes identifiants OAuth ni le trousseau système. Pour l'API Anthropic, il faut définir `ANTHROPIC_API_KEY` dans l'environnement (une clé créée dans la [Claude Console](https://platform.claude.com)).
::

::warning
**`--output-format text` (la valeur par défaut) ne convient pas pour parser la réponse par programme.** Utilise `json` pour une réponse structurée avec métadonnées, ou `stream-json` pour recevoir les tokens au fil de l'eau (utile avec `--verbose --include-partial-messages` pour du streaming en direct).
::
