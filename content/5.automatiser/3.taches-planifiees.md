Claude Code propose deux façons de répéter une tâche automatiquement : `/loop` relance un prompt à intervalle régulier tant que ta session reste ouverte, et les **routines** exécutent une configuration complète dans le cloud, sur une planification, un appel API ou un événement GitHub — sans dépendre de ta machine.

## Quand l'utiliser

Utilise `/loop` pour du sondage ponctuel pendant que tu travailles : surveiller un déploiement, relancer les tests jusqu'à ce qu'ils passent, ou garder un œil sur une PR pendant une session. C'est rapide à lancer mais ça s'arrête dès que tu fermes la session (sauf si tu la mets en arrière-plan).

Utilise une **routine** pour tout ce qui doit continuer à tourner que ton ordinateur soit allumé ou non : un rapport nocturne, une relecture automatique de chaque nouvelle PR, ou une tâche déclenchée par un système externe (alerte, pipeline de déploiement). Les routines s'exécutent sur l'infrastructure cloud d'Anthropic, sans accès à tes fichiers locaux — contrairement à `/loop`, qui tourne dans ta session et voit tout ce qu'elle voit.

## Exemple minimal

::tabs
:::tabs-item{label="/loop en session" icon="i-lucide-repeat"}
Dans une session Claude Code, donne un intervalle et un prompt :

```text [Dans la session Claude Code]
/loop 5m vérifie si le déploiement est terminé et dis-moi ce qui s'est passé
```

Claude convertit l'intervalle en expression cron, planifie la tâche et confirme la fréquence retenue. Les unités acceptées sont `s` (secondes), `m` (minutes), `h` (heures) et `d` (jours).
:::

:::tabs-item{label="Routine cloud" icon="i-lucide-cloud"}
Depuis n'importe quelle session, décris la routine en langage naturel avec `/schedule` :

```text [Dans la session Claude Code]
/schedule revue de PR quotidienne à 9h
```

Claude pose quelques questions de suivi (dépôts concernés, prompt exact) puis enregistre la routine sur ton compte claude.ai. Tu peux aussi tout configurer depuis [claude.ai/code/routines](https://claude.ai/code/routines).
:::
::

## Exemple réaliste

::tabs
:::tabs-item{label="/loop en session" icon="i-lucide-repeat"}
Si tu ne donnes ni intervalle ni prompt, `/loop` utilise un prompt d'entretien intégré : il continue le travail en cours, s'occupe de la PR de la branche courante (commentaires de revue, CI en échec, conflits), puis fait du nettoyage si rien d'autre n'est en attente.

```text [Dans la session Claude Code]
/loop
```

Sans intervalle fixe, Claude choisit lui-même le délai avant la prochaine itération (entre 1 minute et 1 heure) selon ce qu'il observe — plus court si un build est en cours, plus long si tout est calme.

Pour remplacer ce prompt par défaut par le tien, crée un fichier `loop.md` à la racine du projet :

```markdown [.claude/loop.md]
Vérifie la PR de `release/next`. Si la CI est rouge, récupère le log du job
en échec, diagnostique, et pousse un correctif minimal. S'il y a de
nouveaux commentaires de revue, réponds à chacun et résous le fil. Si tout
est vert et calme, dis-le en une ligne.
```

Les modifications de `loop.md` prennent effet dès la prochaine itération, sans avoir à relancer `/loop`.

::::note
Pour arrêter une boucle qui attend sa prochaine itération, appuie sur `Échap` (`Esc`). Une boucle sur intervalle fixe continue jusqu'à ce que tu l'annules explicitement ou que les 7 jours d'expiration automatique soient atteints.
::::
:::

:::tabs-item{label="Routine cloud" icon="i-lucide-cloud"}
Une routine complète associe un prompt, un ou plusieurs dépôts GitHub, des connecteurs (Slack, Linear...) et un ou plusieurs déclencheurs. Exemple de cas d'usage réel : une routine de triage d'alertes.

::::steps{level="3"}
### Créer la routine

Sur [claude.ai/code/routines](https://claude.ai/code/routines), clique sur **New routine**, nomme-la, puis écris un prompt explicite — la routine s'exécute de façon autonome, sans personne pour clarifier une instruction ambiguë :

```text [Prompt de la routine]
Enquête sur l'alerte décrite dans le bloc routine-fire-payload : récupère
la stack trace, corrèle avec les commits récents du dépôt, puis ouvre une
pull request en brouillon avec un correctif proposé et un lien vers
l'alerte.
```

### Ajouter un déclencheur API

Dans la section **Select a trigger**, ajoute un déclencheur **API**, enregistre la routine, puis génère un token (affiché une seule fois — stocke-le dans le coffre secret de ton outil d'alerting).

### Déclencher depuis ton système de monitoring

```bash [Terminal]
curl -X POST https://api.anthropic.com/v1/claude_code/routines/trig_01ABCDEFGHJKLMNOPQRSTUVW/fire \
  -H "Authorization: Bearer sk-ant-oat01-xxxxx" \
  -H "anthropic-beta: experimental-cc-routine-2026-04-01" \
  -H "anthropic-version: 2023-06-01" \
  -H "Content-Type: application/json" \
  -d '{"text": "Alerte Sentry SEN-4521 déclenchée en prod. Stack trace en pièce jointe."}'
```

La réponse renvoie l'identifiant et l'URL de la session créée, à ouvrir dans un navigateur pour suivre le déroulé en direct.
::::
:::
::

## Pièges fréquents

::warning
**Une boucle `/loop` autopilotée n'est pas restaurée après un `--resume`.** Les tâches planifiées avec un intervalle fixe (`CronCreate`) sont bien restaurées quand tu reprends une session avec `--resume` ou `--continue`, mais une boucle à intervalle choisi dynamiquement par Claude ne l'est pas — il faut retaper `/loop` pour la relancer. Dans tous les cas, une boucle ne se déclenche que pendant que Claude Code tourne et est inactif : fermer le terminal l'arrête.
::

::note
**Une tâche planifiée récurrente expire au bout de 7 jours.** C'est une limite volontaire pour éviter qu'une boucle oubliée tourne indéfiniment : elle se déclenche une dernière fois puis se supprime. Pour une automatisation qui doit durer plus longtemps, utilise une routine cloud plutôt que `/loop`.
::

::caution
**L'heure exacte d'un déclenchement peut varier (jitter).** Pour éviter que toutes les sessions n'appellent l'API au même instant, le planificateur ajoute un décalage : jusqu'à 30 minutes pour une tâche récurrente (ou jusqu'à la moitié de l'intervalle si celui-ci est inférieur à une heure), et jusqu'à 90 secondes en avance pour une tâche ponctuelle prévue pile à l'heure ou à la demie. Si l'horaire précis compte, choisis une minute qui n'est ni `:00` ni `:30`.
::

::warning
**Une routine cloud n'a pas accès à tes fichiers locaux.** Elle clone le dépôt à chaque exécution à partir de sa branche par défaut — elle ne voit donc ni ta configuration locale, ni des fichiers non commités. Pour une automatisation qui a besoin de ton environnement local (fichiers, outils installés), utilise plutôt une tâche planifiée côté Desktop ou `/loop` dans une session ouverte sur ta machine.
::

::note
**Le texte envoyé à une routine via l'API n'est pas traité comme une instruction directe.** Il arrive entouré d'un bloc `<routine-fire-payload>` qui le signale comme donnée non fiable — le prompt enregistré de la routine doit explicitement faire référence à ce bloc pour que Claude agisse dessus. Sans ça, le texte envoyé est traité comme du contexte inerte.
::
