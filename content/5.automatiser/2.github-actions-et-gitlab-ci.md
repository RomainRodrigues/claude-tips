Claude Code peut s'exécuter comme une étape de pipeline CI/CD : il répond à un commentaire `@claude` sur une issue ou une pull/merge request, ou lance une tâche automatiquement sur un déclencheur (planification, ouverture de PR...). Sur GitHub, ça passe par l'action officielle `anthropics/claude-code-action` ; sur GitLab, par un job classique qui installe et appelle la CLI `claude`.

## Quand l'utiliser

Pour déléguer des tâches répétitives à Claude sans quitter ton flux Git habituel : transformer une issue en pull request, relire chaque PR automatiquement, corriger un bug signalé en commentaire, ou générer un rapport quotidien. L'avantage par rapport au mode headless lancé à la main : tout se déclenche depuis GitHub/GitLab lui-même (mention, événement, planification), et le résultat (commentaire, commit, MR) apparaît directement dans ton dépôt.

## Exemple minimal

::tabs
:::tabs-item{label="GitHub Actions" icon="i-simple-icons-github"}
Le plus rapide : lance `/install-github-app` depuis une session Claude Code, dans le dépôt à connecter (nécessite le [GitHub CLI](https://cli.github.com) authentifié avec `gh auth login`, et un accès admin au dépôt). Claude Code installe la GitHub App, crée le secret d'authentification, et ouvre une pull request avec le fichier de workflow prêt à fusionner.

En configuration manuelle, installe la [Claude GitHub App](https://github.com/apps/claude), ajoute un secret de dépôt `ANTHROPIC_API_KEY` (ou `CLAUDE_CODE_OAUTH_TOKEN` généré avec `claude setup-token` si tu utilises un abonnement Claude), puis copie ce workflow dans `.github/workflows/claude.yml` :

```yaml [.github/workflows/claude.yml]
name: Claude Code
on:
  issue_comment:
    types: [created]
  pull_request_review_comment:
    types: [created]
jobs:
  claude:
    if: contains(github.event.comment.body, '@claude')
    runs-on: ubuntu-latest
    permissions:
      contents: write
      pull-requests: write
      issues: write
      id-token: write
      actions: read
    steps:
      - uses: actions/checkout@v6
        with:
          fetch-depth: 1
      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
```

Une fois le workflow fusionné, mentionne `@claude` dans un commentaire d'issue ou de PR pour tester.
:::

:::tabs-item{label="GitLab CI/CD" icon="i-simple-icons-gitlab"}
<!-- VERIFY: la doc officielle qualifie cette intégration GitLab CI/CD de bêta ("currently in beta"), maintenue par GitLab et non par Anthropic. -->

Ajoute une variable CI/CD masquée `ANTHROPIC_API_KEY` (**Settings → CI/CD → Variables**), puis un job dans `.gitlab-ci.yml` :

```yaml [.gitlab-ci.yml]
stages:
  - ai

claude:
  stage: ai
  image: node:24-alpine3.21
  rules:
    - if: '$CI_PIPELINE_SOURCE == "web"'
    - if: '$CI_PIPELINE_SOURCE == "merge_request_event"'
  variables:
    GIT_STRATEGY: fetch
  before_script:
    - apk update
    - apk add --no-cache git curl bash
    - curl -fsSL https://claude.ai/install.sh | bash
    - export PATH="$HOME/.local/bin:$PATH"
  script:
    - >
      claude
      -p "${AI_FLOW_INPUT:-'Relis cette MR et implémente les changements demandés'}"
      --permission-mode acceptEdits
      --allowedTools "Bash Read Edit Write mcp__gitlab"
```

Teste-le en lançant le job manuellement depuis **CI/CD → Pipelines**, ou en le déclenchant sur une merge request.
:::
::

## Exemple réaliste

::tabs
:::tabs-item{label="GitHub Actions" icon="i-simple-icons-github"}
Une revue de PR automatique à chaque ouverture ou mise à jour, en installant le plugin officiel `code-review` :

```yaml [.github/workflows/claude-code-review.yml]
name: Code Review
on:
  pull_request:
    types: [opened, synchronize, ready_for_review, reopened]
jobs:
  review:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pull-requests: read
      issues: read
      id-token: write
    steps:
      - uses: actions/checkout@v6
        with:
          fetch-depth: 1
      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
          plugin_marketplaces: "https://github.com/anthropics/claude-code.git"
          plugins: "code-review@claude-code-plugins"
          prompt: "/code-review:code-review --comment ${{ github.repository }}/pull/${{ github.event.pull_request.number }}"
          claude_args: '--allowedTools "mcp__github_inline_comment__create_inline_comment"'
```

Claude poste la revue directement sur la PR (commentaire en ligne par problème détecté, ou un seul commentaire de synthèse s'il n'y a rien à signaler). Il saute les PR en brouillon, celles qu'il juge inutiles à relire, et celles qu'il a déjà commentées.

Autre cas : un rapport quotidien planifié, sans avoir besoin de cloner le dépôt puisque tout passe par l'API GitHub :

```yaml [.github/workflows/daily-report.yml]
name: Daily Report
on:
  schedule:
    - cron: "0 9 * * *"
jobs:
  report:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      issues: read
      id-token: write
    steps:
      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
          prompt: "Fais un résumé des commits d'hier et des issues ouvertes"
          claude_args: |
            --model claude-opus-4-8
            --allowedTools "mcp__github__list_commits,mcp__github__list_issues"
```

::::note
GitHub ne déclenche les workflows planifiés (`schedule`) que sur la branche par défaut, et désactive automatiquement la planification après 60 jours sans activité sur un dépôt public.
::::
:::

:::tabs-item{label="GitLab CI/CD" icon="i-simple-icons-gitlab"}
Pour router l'inférence vers ton propre compte cloud plutôt que vers l'API Claude directement (utile en entreprise pour des besoins de résidence des données), authentifie-toi par OIDC vers Amazon Bedrock :

```yaml [.gitlab-ci.yml]
stages:
  - ai

claude-bedrock:
  stage: ai
  image: node:24-alpine3.21
  rules:
    - if: '$CI_PIPELINE_SOURCE == "web"'
  id_tokens:
    GITLAB_OIDC_TOKEN:
      aud: https://gitlab.example.com
  before_script:
    - apk add --no-cache bash curl jq git aws-cli
    - curl -fsSL https://claude.ai/install.sh | bash
    - export PATH="$HOME/.local/bin:$PATH"
    - export AWS_WEB_IDENTITY_TOKEN_FILE="/tmp/oidc_token"
    - printf "%s" "$GITLAB_OIDC_TOKEN" > "$AWS_WEB_IDENTITY_TOKEN_FILE"
    - >
      aws sts assume-role-with-web-identity
      --role-arn "$AWS_ROLE_TO_ASSUME"
      --role-session-name "gitlab-claude-$(date +%s)"
      --web-identity-token "file://$AWS_WEB_IDENTITY_TOKEN_FILE"
      --duration-seconds 3600 > /tmp/aws_creds.json
    - export AWS_ACCESS_KEY_ID="$(jq -r .Credentials.AccessKeyId /tmp/aws_creds.json)"
    - export AWS_SECRET_ACCESS_KEY="$(jq -r .Credentials.SecretAccessKey /tmp/aws_creds.json)"
    - export AWS_SESSION_TOKEN="$(jq -r .Credentials.SessionToken /tmp/aws_creds.json)"
  script:
    - >
      claude
      -p "${AI_FLOW_INPUT:-'Implémente les changements demandés et ouvre une MR'}"
      --permission-mode acceptEdits
      --allowedTools "Bash Read Edit Write mcp__gitlab"
  variables:
    AWS_REGION: "us-west-2"
    CLAUDE_CODE_USE_BEDROCK: "1"
```

Ça suppose un rôle IAM avec accès Amazon Bedrock, déjà configuré pour faire confiance au fournisseur OIDC de GitLab (`AWS_ROLE_TO_ASSUME` et `AWS_REGION` en variables CI/CD).
:::
::

## Pièges fréquents

::warning
**Ne commite jamais une clé API ou un token OAuth directement dans le dépôt.** Passe toujours par les secrets (GitHub Secrets ou variables CI/CD GitLab masquées) et référence-les avec `${{ secrets.ANTHROPIC_API_KEY }}` (GitHub) ou une variable d'environnement (GitLab).
::

::caution
**Les commits de Claude ne redéclenchent pas ta CI sur GitHub.** GitHub ne déclenche pas de workflow sur des commits faits avec le `GITHUB_TOKEN` par défaut. Si tu passes `github_token: ${{ secrets.GITHUB_TOKEN }}` à l'action, retire-le pour que Claude s'authentifie via la GitHub App (ou fournis un token d'app personnalisé) — sinon tes vérifications CI ne se relancent jamais sur les commits de Claude.
::

::note
**Seule une personne avec accès en écriture peut déclencher Claude via mention.** Sur les événements d'issue et de PR, l'action GitHub vérifie que l'auteur du commentaire a un accès en écriture au dépôt, et rejette systématiquement un compte bot sauf s'il est explicitement listé dans `allowed_bots`. C'est voulu : ça évite qu'un bot ou un compte externe déclenche Claude en boucle.
::

::warning
**Sur GitLab, l'intégration est en bêta et maintenue par GitLab, pas par Anthropic.** Les flags et paramètres exacts peuvent varier selon la version de `@anthropic-ai/claude-code` installée dans le job — lance `claude --help` dans le job pour vérifier les options disponibles avant de t'appuyer dessus en production.
::

::note
**Limite les coûts avec `--max-turns` et des timeouts.** Chaque exécution consomme à la fois des minutes CI (GitHub Actions ou runners GitLab) et des tokens d'API. Fixe `--max-turns` dans `claude_args` (GitHub) ou dans le prompt (GitLab), ajoute un timeout au niveau du job, et limite les exécutions parallèles avec les contrôles de concurrence de ta plateforme.
::
